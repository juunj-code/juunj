# 프로토타입: 전투 공식 페이싱 검증 (throwaway)

**상태**: 완료 — throwaway. 메인 게임 코드(`src/`)로 승격되지 않음. 삭제해도 무방.

## 프로토타입 브리프

```
QUESTION:     #6 전투-공식.md의 턴제 전투 공식이 실제 수치로 봤을 때
              (1) 일반 층 전투가 3~5턴 안에 합리적으로 끝나는가,
              (2) 스킬 vs 기본 공격이 의미 있는 트레이드오프인가,
              (3) "솔로도 최강" 필라가 예시 스탯으로도 성립하는가?
CORE VERB:    턴마다 SP 되면 스킬, 아니면 기본 공격 — 최저 HP 적 포커스 파이어
THROWAWAY?:   yes — prototypes/combat-core/, src/에서 임포트 안 함
TIMEBOX:      60분
KEEP IF:      일반 층 전투가 짧고 스킬 사용이 의미 있으며, 솔로 보스전도 승산 있음
KILL IF:      전투가 즉사하거나 질질 끌리거나, 스킬을 쓸 이유가 없음
```

## 왜 Godot이 아니라 Python인가

이 환경에 Godot 엔진 바이너리가 설치되어 있지 않다(`godot`/`godot4` 커맨드 없음). 이 프로토타입의
질문은 "입력 체감"이 아니라 "수치 페이싱"이라 실제 엔진 없이도 답할 수 있다고 판단해, `#6`의 공식을
Python으로 그대로 이식한 로직 시뮬레이션으로 대체했다. **이 대체가 검증하지 못하는 것**: 실제 터치
입력감, 애니메이션 타이밍, UI 반응성 — 이건 여전히 실제 Godot 빌드 없이는 알 수 없다.

## 결과 (500회 시뮬레이션, seed=42)

| 시나리오 | 승률 | 평균 턴 | 스킬 사용률 |
|---|---|---|---|
| 1층 (적 1마리, 딜러+탱커 파티) | 100.0% | 2.00턴 | 25.0% |
| 2층 (적 2마리) | 100.0% | 3.00턴 | 33.3% |
| 3층 (적 3마리, 동일 speed 타이브레이크 스트레스) | 100.0% | 4.00턴 | 42.9% |
| **보스방 (1:1 솔로도 최강 검증)** | **0.0%** | 13.00턴 | 48.0% |

## 판정

**KEEP (공식/턴 루프 메커니즘 자체)** — 일반 층 전투는 2~4턴으로 빠르고, 층이 깊어질수록 스킬
사용률이 자연스럽게 올라간다(25%→43%, 적이 많을수록 SP 자원 관리가 더 중요해짐 — 의미 있는
트레이드오프). 즉사도, 질질 끌림도 없음. 부동소수점 엡실론 가드·2차 정렬 타이브레이크도 시뮬레이션
전체에서 한 번도 깨지지 않았다. 공식 자체와 턴 루프 구조는 그대로 구현해도 될 근거가 생겼다.

**REFACTOR 신호 (보스 스탯 튜닝)** — `#11 적-데이터`의 보스 예시 스탯(hp=220, atk=20, def=16,
spd=6)과 `#10 동료-데이터`의 예시 스탯(hp=100, atk=18, def=15, spd=5)을 그대로 대입하면, 솔로
동료가 보스에게 **500번 중 0번** 이긴다. 원인: 보스 방어력(16)이 동료 기본 공격(18×1.0−16=2)을
거의 무효화하고, 표준 스킬(1.5배)로도 겨우 11의 데미지 — 반대로 보스는 동료 방어(15)를 뚫고
스킬 기준 매턴 ~11, 기본 기준 매턴 ~5를 꽂는다. 220 HP를 깎는 속도보다 동료 100 HP가 깎이는
속도가 훨씬 빠르다. **이건 공식이 고장난 게 아니라 예시 스탯 조합이 "솔로도 최강" 필라와 충돌한다는
신호** — 시뮬레이션은 companion의 "강 스킬"(2.0배 티어)이나 `#4 장비` 보정을 포함하지 않은
보수적인 케이스라, 실제로는 장비로 이 갭이 메워질 수도 있다. 다만 장비 없이 순수 스탯만으로는
필라가 성립하지 않는다는 게 확인됐으니, 밸런스 담당자가 보스 스탯 곡선 또는 강 스킬 접근성을
재검토할 가치가 있다 — GDD를 다시 열 정도의 버그는 아니지만(승인된 예시 수치의 정확성 문제),
실제 구현 전 밸런스 패스에서 반드시 재확인.
