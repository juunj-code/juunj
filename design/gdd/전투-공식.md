# 전투 공식 (Combat Formula)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-24
> **Implements Pillar**: 전략은 단순하게, 조합은 깊게
> **Creative Director Review**: Skipped — Lean 모드

## Overview

전투 공식 시스템은 바람의 탑 턴제 전투의 모든 수치 계산을 정의하는 Core 레이어 시스템이다. 데미지 계산 · 스킬 데미지 · 턴 순서 결정 · SP(스킬 포인트) 회복 · 전투 종료 조건 5개 공식을 소유하며, #10 동료 데이터와 #11 적 데이터가 확정한 스탯 범위를 입력값으로 삼아 "#1 턴제 전투"가 호출하는 단일 계산 계층이다. 이 시스템은 "어떤 액션을 고를지"(#1 턴제 전투) · "누가 어떤 스탯을 가지는지"(#10·#11) · "버프/디버프 효과"(#12 상태이상)를 소유하지 않는다 — 오직 수치를 받아 수치를 반환하는 순수 함수 계층이다. 필라 4("전략은 단순하게, 조합은 깊게")를 수치적으로 실현한다: 개별 공식은 단순하나, 스탯 범위·스킬 배율·속도 조합이 만드는 전략적 깊이는 데이터에서 나온다.

## Player Fantasy

플레이어는 공식을 보지 않는다. 대신 "이 동료 조합이 왜 이렇게 강하지?"를 발견하는 순간을 경험한다.

- **예측 가능한 수치**: 적의 ATK가 눈에 보이면 "우리 DEF로 버틸 수 있겠다"는 판단이 선다. 공식이 불투명하면 이 판단이 불가능해진다.
- **스킬 사용의 타이밍 쾌감**: SP가 쌓이는 걸 보면서 "이제 쓴다"는 결정의 무게감. 공식이 단순해야 이 타이밍 감각이 직관적으로 작동한다.
- **조합의 발견**: "이 동료들을 함께 쓰면 한 방에 끝나네" — 단순한 공식 위에서 스탯 조합이 만드는 시너지를 플레이어 스스로 발견한다.

## Detailed Rules

### 전투 흐름 개요

```
턴 시작 → 속도순 정렬(turn order) → 현재 순서 유닛 액션 선택
         ↓
   [기본 공격 or 스킬]
         ↓
  데미지 계산 → HP 차감 → 전투 종료 체크 → 다음 유닛
```

### 액션 유형

| 액션 | 조건 | SP 변화 |
|------|------|---------|
| 기본 공격 | 항상 가능 | 없음 |
| 스킬 사용 | `current_sp >= skill.cost_sp` | `-skill.cost_sp` |
| SP 회복 | 매 턴 자동 | `+SP_GAIN_PER_TURN` |

SP 회복은 액션 전에 처리한다 (같은 턴에 회복 + 스킬 사용 가능).

### Core Rules

1. **모든 데미지는 최소 1**: `max(1, 계산값)` — 어떤 조합에서도 완전 무효화 없음.
2. **HP는 0 미만으로 내려가지 않음**: `current_hp = max(0, current_hp - damage)`.
3. **공식은 정수 연산**: `floor()` 적용, 소수점 버림 — 수치 예측 가능성 보장.
4. **상태이상 효과는 이 시스템 외부**: #12 상태이상이 ATK·DEF 수정치를 넘기면, 이 시스템은 수정된 값을 입력으로 받아 계산한다. 공식 자체는 변하지 않는다.

## Formulas

### ① 기본 공격 데미지

```
damage = max(1, atk - def)
```

| 변수 | 출처 | 설명 |
|------|------|------|
| `atk` | 공격 유닛의 `base_atk` (+장비·버프 수정) | 공격력 |
| `def` | 방어 유닛의 `base_def` (+장비·버프 수정) | 방어력 |

**검증 (스탯 범위 극단값):**

| 시나리오 | 계산 | 결과 |
|----------|------|------|
| 동료 최강 딜러 vs 일반 적 최약 방어 | max(1, 30 − 3) | **27** |
| 동료 최약 딜러 vs 동료 최강 방어 (오사격 가정) | max(1, 10 − 20) | **1** |
| 일반 적 최강 vs 동료 최약 방어 | max(1, 18 − 5) | **13** |
| 보스 최강 vs 동료 최강 방어 | max(1, 25 − 20) | **5** |
| 보스 최강 vs 동료 최약 방어 | max(1, 25 − 5) | **20** |

보스가 동료 최약 HP(60)에 20 데미지: 3턴 생존 가능. 60HP 탱커는 (25−20=5) 데미지로 12턴 생존 — 파티 조합 전략의 근거.

---

### ② 스킬 데미지

```
damage = max(1, floor(atk * multiplier) - def)
```

| 변수 | 출처 | 설명 |
|------|------|------|
| `atk` | 공격 유닛의 `base_atk` (+장비·버프 수정) | 공격력 |
| `multiplier` | `SkillData.damage_multiplier` | 스킬 배율 (1.0 = 기본 공격과 동일) |
| `def` | 방어 유닛의 `base_def` (+장비·버프 수정) | 방어력 |

**MVP 스킬 배율 범위 (SkillData 설계 기준):**

| 배율 등급 | `damage_multiplier` 범위 | 용도 |
|-----------|--------------------------|------|
| 약 스킬 | 1.0 ~ 1.2 | 부가 효과(상태이상)가 메인, 데미지는 보조 |
| 표준 스킬 | 1.5 | 일반적인 공격 스킬 |
| 강 스킬 | 2.0 | 높은 SP 비용, 강력한 한 방 |

**검증 (표준 스킬 1.5 배율):**

| 시나리오 | 계산 | 결과 |
|----------|------|------|
| 동료 최강 딜러(30) × 1.5 vs 일반 적 최약 방어(3) | max(1, floor(45) − 3) | **42** |
| 동료 최약 딜러(10) × 1.5 vs 동료 최강 방어(20) | max(1, floor(15) − 20) | **1** |
| 보스(20 ATK) × 2.0 vs 동료 최약 방어(5) | max(1, floor(40) − 5) | **35** |

보스 강 스킬(35 데미지)은 60HP 동료를 거의 확정 1격 — 보스 스킬 사용은 전투 분기점.

---

### ③ 턴 순서 (Turn Order)

```
turn_order = combatants.sort_by(base_spd, descending)
tie_break   = companion before enemy (same speed)
```

| 변수 | 출처 | 설명 |
|------|------|------|
| `base_spd` | 각 유닛의 `base_spd` (+버프 수정) | 속도 |

매 턴 시작 시 전체 재정렬 (버프로 속도 변동 가능). 같은 속도: 동료 우선 (플레이어 유리, 필라 3 "솔로도 최강" 지원).

**검증 (MVP 스탯 예시):**

| 유닛 | base_spd | 순서 |
|------|----------|------|
| 동료 지원형 | 9 | 1번 |
| 일반 적 속도형 | 8 | 2번 |
| 동료 딜러형 | 8 | 3번 (동속도 동료 후순위 — 동료끼리는 파티 편성 순서) |
| 동료 밸런스형 | 6 | 4번 |
| 보스 | 6 | 5번 (동속도 → 동료 우선) |
| 동료 탱커형 | 3 | 6번 |
| 일반 적 탱커형 | 2 | 7번 |

### ④ SP 시스템

```
sp_start    = 0                          # 전투 시작 시 모든 유닛
sp_recovery = min(SP_MAX, sp + SP_GAIN_PER_TURN)  # 매 턴 시작 전
sp_cost     = SkillData.cost_sp          # 스킬 사용 시 차감
```

| 상수 | 값 | 설명 |
|------|----|------|
| `SP_MAX` | 5 | SP 최대값 |
| `SP_GAIN_PER_TURN` | 1 | 턴당 SP 회복량 |

MVP 스킬 `cost_sp` 기준:

| SP 비용 | 스킬 등급 | 최초 사용 가능 턴 |
|---------|-----------|-----------------|
| 2 | 약/표준 스킬 | 2턴차 |
| 3 | 강 스킬 | 3턴차 |

적도 동일한 SP 시스템 사용 — 보스 강 스킬은 3턴차부터 위협.

---

### ⑤ 전투 종료 조건

```
victory = all(enemy.current_hp <= 0 for enemy in active_enemies)
defeat  = all(companion.current_hp <= 0 for companion in active_companions)
```

| 결과 | 조건 | 다음 행동 |
|------|------|-----------|
| 승리 | 모든 적 HP = 0 | #13 런 상태 관리에 "전투 완료" 신호 |
| 패배 | 모든 동료 HP = 0 | #13 런 상태 관리에 "런 실패" 신호 |

판정은 매 HP 차감 직후 즉시 체크. 마지막 적 처치와 마지막 동료 처치가 같은 액션에서 발생하면 → **승리 우선** (플레이어 유리, 필라 3 지원).

## Edge Cases

- **ATK < DEF 인 경우**: `max(1, ...)` 로 최소 1 데미지 보장. 어떤 조합에서도 완전 무효화 없음.

- **스킬 배율로 인해 데미지가 음수가 되는 경우** (이론상 불가 — 배율이 1.0 이상으로 설계됨): 발생 시에도 `max(1, ...)` 가 보호. `push_warning("Skill multiplier below 1.0 on skill: [id]")`.

- **동속도 동료 간 순서**: 파티 편성 인덱스(0·1·2) 기준 오름차순. 인덱스 0이 먼저. 파티 편성 UI가 순서를 암시해야 함 — `#15 파티 구성` GDD에 "첫 번째 슬롯이 동속도 선행" 명시 필요.

- **승리/패배 동시 발생** (마지막 적의 반격으로 마지막 동료 동시 사망): 승리 우선 처리 → #16 런 결과에 "승리" 신호 전달. 데미지 적용 순서가 이 케이스를 결정하므로 #1 턴제 전투가 "공격자 피해 → 방어자 피해" 순서를 고정해야 함.

- **상태이상으로 수정된 ATK·DEF가 음수인 경우**: 이 시스템은 입력값을 신뢰. `max(0, modified_stat)` 클램핑은 #12 상태이상 시스템 책임 — 이 시스템에서 클램핑하지 않는다 (단일 책임 원칙).

- **SP가 cost_sp 미만인데 스킬 사용 요청**: 이 공식 시스템은 조건 검사를 하지 않는다. 호출 전 `#1 턴제 전투`가 `current_sp >= cost_sp` 검증 후 호출해야 하며, 검증 없이 호출되면 데미지는 계산하되 `push_warning` 기록.

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 너무 낮을 때 | 너무 높을 때 |
|--------|-----------|-----------|-------------|-------------|
| 스킬 표준 배율 `multiplier` | 1.5 | 1.3 ~ 2.0 | 스킬 사용 동기 없음 | 기본 공격 사용 의미 없음 |
| 스킬 강 배율 `multiplier` | 2.0 | 1.8 ~ 2.5 | 강 스킬과 표준 스킬 차이 없음 | 한 방 원킬 → 전략 깊이 없음 |
| `SP_MAX` | 5 | 4 ~ 6 | 스킬 너무 자주 사용 | SP 잘 안 쌓임 → 스킬 사용 빈도 낮음 |
| `SP_GAIN_PER_TURN` | 1 | 1 (고정 권장) | — | 스킬이 매 턴 가능 → 기본 공격 의미 없음 |
| 표준 스킬 `cost_sp` | 2 | 1 ~ 3 | 2턴마다 스킬 → 기본 공격 없음 | 5턴 이상 기다림 → 지루 |
| 강 스킬 `cost_sp` | 3 | 2 ~ 4 | 표준 스킬과 차이 없음 | 보스전에서도 1~2회밖에 못 씀 |
| 동속도 타이브레이크 | 동료 우선 | — | 적 우선 시 초반 압박 과도 | — |

## Visual/Audio Requirements

이 시스템은 시각/오디오 자산을 소유하지 않는다. 계산 결과(데미지 수치, SP 변화)를 신호로 발신하면 `#1 턴제 전투`가 피격 애니메이션을 실행하고 `#21 오디오`가 SFX를 재생한다.

## UI Requirements

이 시스템은 UI를 소유하지 않는다. 데미지 수치 팝업·SP 바·턴 순서 표시는 `#20 UI/HUD` 소유. 이 시스템은 계산 결과 숫자만 반환한다.

## Acceptance Criteria

1. (공식 ① – 기본 데미지) GIVEN atk=30, def=3인 상태에서 WHEN 기본 공격 데미지를 계산하면 THEN 결과는 27이다.

2. (공식 ① – 최소 보장) GIVEN atk=10, def=20인 상태에서 WHEN 기본 공격 데미지를 계산하면 THEN 결과는 1이다 (음수 없음).

3. (공식 ② – 스킬 데미지) GIVEN atk=30, multiplier=1.5, def=3인 상태에서 WHEN 스킬 데미지를 계산하면 THEN 결과는 42이다 (floor(45)−3).

4. (공식 ② – 스킬 최소 보장) GIVEN atk=10, multiplier=1.5, def=20인 상태에서 WHEN 스킬 데미지를 계산하면 THEN 결과는 1이다.

5. (공식 ③ – 턴 순서) GIVEN 속도 [9, 8, 8, 6, 6, 3, 2]인 유닛 7개(동속도 포함 동료 우선)가 있을 때 WHEN 턴 순서를 정렬하면 THEN 순서는 [spd9-동료, spd8-동료, spd8-적, spd6-동료, spd6-적, spd3-동료, spd2-적]이다.

6. (공식 ④ – SP 회복) GIVEN 전투 시작 시 sp=0이고 SP_GAIN_PER_TURN=1인 상태에서 WHEN 2턴이 경과하면 THEN sp=2이고 cost_sp=2인 스킬을 사용할 수 있다.

7. (공식 ④ – SP 상한) GIVEN sp=4이고 SP_MAX=5인 상태에서 WHEN 턴이 시작되면 THEN sp=5로 회복되고 6이 되지 않는다.

8. (공식 ⑤ – 승리 조건) GIVEN 마지막 적의 HP가 5이고 동료가 10 데미지를 가하는 상태에서 WHEN 공격이 적중하면 THEN 적 HP는 0이 되고 즉시 승리 판정이 발생한다.

9. (공식 ⑤ – 승리/패배 동시) GIVEN 마지막 적의 반격으로 마지막 동료의 HP가 0이 되는 순간이 동일 액션 내 발생할 때 WHEN 판정하면 THEN 승리가 패배보다 우선 적용된다.

10. (HP 하한) GIVEN 어떤 유닛의 현재 HP가 5이고 100 데미지를 받을 때 WHEN 데미지를 적용하면 THEN current_hp는 0이고 -95가 아니다.
