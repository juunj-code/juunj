> **Author**: 사용자 + Claude Code

## Overview

장비 시스템은 동료에게 장착하는 아이템을 정의하고 전투 스탯에 보정치를 제공하는 Economy 레이어 시스템이다. MVP 장비는 두 슬롯(무기·방어구)에 각각 하나씩 장착하며, ATK 또는 DEF에 고정값을 더한다. 장비는 런 시작 전 파티 구성 화면에서 장착하고 전투 중 변경 불가. 드롭은 전투방 클리어 후 50% 확률로 1개. 이 시스템은 장비 데이터 구조·드롭 로직·장착 상태를 소유하며, 전투 스탯 적용은 #6 전투 공식이 effective 스탯을 계산할 때 장비 보정치를 포함해 처리한다.

## Player Fantasy

"이 무기 달면 이번 런 더 강해질 수 있다" — 런 시작 전 작은 최적화 결정.

## Detailed Rules

### 장비 데이터 구조

```gdscript
# EquipmentData (정적 데이터 — 동료 데이터와 동일한 방식으로 Dictionary 또는 Resource로 정의)
{
  "id": "iron_sword",
  "name": "철검",
  "slot": "weapon",   # "weapon" | "armor"
  "stat": "atk",      # "atk" | "def"
  "bonus": 3          # 고정 보정값 (int)
}
```

MVP 장비 목록 (6종):

| ID | 이름 | 슬롯 | 스탯 | 보정값 |
|----|------|------|------|--------|
| `iron_sword` | 철검 | weapon | ATK | +3 |
| `steel_sword` | 강철검 | weapon | ATK | +5 |
| `power_ring` | 힘의 반지 | weapon | ATK | +2 |
| `leather_armor` | 가죽 갑옷 | armor | DEF | +3 |
| `chain_mail` | 체인 메일 | armor | DEF | +5 |
| `shield_bracelet` | 방패 팔찌 | armor | DEF | +2 |

### 장착 상태 (RunManager 내 CompanionRunState에 포함)

```gdscript
# CompanionRunState 확장 필드
{
  "weapon_slot": "iron_sword",    # String | null
  "armor_slot": null              # String | null
}
```

런 시작 시 #15 파티 구성에서 설정. 런 종료 후 초기화 (장비는 런 간 영속 안 됨 — MVP).

### 드롭 로직

```
전투방 클리어 시:
  if randf() < DROP_CHANCE:
    item_id = equipment_pool.pick_random()
    RunManager.inventory.append(item_id)
    emit equipment_dropped(EquipmentData[item_id])
```

MVP 인벤토리: `RunManager`가 보유하는 `Array[String]` (equipment_id 목록). 한도 없음.

### 스탯 보정 적용

이 시스템은 스탯을 직접 수정하지 않는다. 전투 시작 시 또는 조회 시:

```gdscript
func get_effective_atk(companion_state: CompanionRunState) -> int:
    var base := CompanionData[companion_state.companion_id].base_atk
    var weapon := EquipmentData.get(companion_state.weapon_slot)
    return base + (weapon.bonus if weapon and weapon.stat == "atk" else 0)

func get_effective_def(companion_state: CompanionRunState) -> int:
    var base := CompanionData[companion_state.companion_id].base_def
    var armor := EquipmentData.get(companion_state.armor_slot)
    return base + (armor.bonus if armor and armor.stat == "def" else 0)
```

# ponytail: MVP 장비 6종·파티 3명이므로 매 조회 시 계산. 캐시는 장비 수 증가 시 추가.

### Core Rules

1. **슬롯당 1개**: weapon 슬롯에 무기 1개, armor 슬롯에 방어구 1개. 교체 시 기존 장비는 인벤토리로 반환.
2. **런 내 임시 보유**: 장비는 런이 끝나면 사라진다 (영속 장비는 Full Vision).
3. **전투 중 변경 불가**: 장착 변경은 파티 구성 화면에서만.
4. **드롭은 전투방 클리어 후**: 히든방·보스방 드롭 없음 — YAGNI.

## Formulas

**드롭 확률:**
```
DROP_CHANCE = 0.5
전투방 클리어 후 randf() < DROP_CHANCE → 드롭 발생
드롭 아이템 = equipment_pool.pick_random()  # 6종 균등
```

**스탯 보정:**
```
effective_atk = base_atk + (weapon.bonus if weapon and weapon.stat == "atk" else 0)
effective_def = base_def + (armor.bonus if armor and armor.stat == "def" else 0)
```

예시: base_atk=10, iron_sword(ATK+3) 장착 → effective_atk=13.

## Edge Cases

- **인벤토리에 같은 장비 2개**: 허용. MVP에서 ID 중복 허용 — 장비 수집이 목적이 아니라 현재 장착이 목적.

- **보스방 클리어 후 드롭**: 드롭 없음. Full Vision에서 보스 고유 드롭 추가.

- **장비 없이 전투 시작**: `weapon_slot = null`, `armor_slot = null` → 보정값 0 → 정상 동작.

- **동료별 장비 제한**: MVP — 모든 장비가 모든 동료에 장착 가능 (클래스 제한 없음). Full Vision에서 직업별 장비 제한 추가.

- **슬롯 교체 중 인벤토리 반환**: 동료 A의 weapon_slot="iron_sword" 상태에서 "steel_sword" 장착 → "iron_sword"가 RunManager.inventory로 반환. 인벤토리에 중복 아이템 생길 수 있음 (허용).

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 설명 |
|--------|-----------|-----------|------|
| DROP_CHANCE | 50% | 30~70% | 낮으면 장비 희소, 높으면 항상 있음 |
| 무기 ATK 보정 범위 | +2~+5 | +1~+8 | 전투 공식 밸런스와 연동 |
| 방어구 DEF 보정 범위 | +2~+5 | +1~+8 | 동일 |
| MVP 장비 종류 | 6종 | MVP 고정 | 다양성은 Full Vision에서 확장 |

## Acceptance Criteria

1. (드롭 발생) GIVEN 전투방 클리어 WHEN 드롭 확률 판정 성공 THEN 장비 풀에서 1개 아이템이 선택되어 RunManager.inventory에 추가되고 `equipment_dropped` 신호가 발신된다.

2. (드롭 미발생) GIVEN 전투방 클리어 WHEN 드롭 확률 판정 실패 THEN inventory 변화 없이 던전 탐색이 재개된다.

3. (장착 스탯 반영) GIVEN 동료 base_atk=10, weapon_slot="iron_sword"(ATK+3) WHEN `get_effective_atk()` 호출 THEN 13이 반환된다.

4. (슬롯 없음) GIVEN `weapon_slot=null` WHEN `get_effective_atk()` 호출 THEN base_atk 그대로 반환된다.

5. (슬롯 교체) GIVEN weapon_slot="iron_sword" 상태에서 WHEN "steel_sword" 장착 THEN weapon_slot이 "steel_sword"로 교체되고 "iron_sword"가 inventory로 반환된다.

6. (보스방 드롭 없음) GIVEN 보스방 클리어 WHEN 처리 THEN `equipment_dropped` 신호가 발신되지 않는다.

7. (히든방 드롭 없음) GIVEN 히든방 진입·처리 완료 WHEN 처리 THEN `equipment_dropped` 신호가 발신되지 않는다.
