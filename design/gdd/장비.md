# 장비 (Equipment)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-26
> **Implements Pillar**: 전략은 단순하게, 조합은 깊게
> **Creative Director Review**: Skipped — Lean 모드

## Overview

장비 시스템은 동료에게 장착하는 아이템을 정의하고 전투 스탯에 보정치를 제공하는 Economy 레이어 시스템이다. MVP 장비는 두 슬롯(무기·방어구)에 각각 하나씩 장착하며, ATK 또는 DEF에 고정값을 더한다. 장비는 런 시작 전 파티 구성 화면에서 장착하고 전투 중 변경 불가. 드롭은 전투방 클리어 후 50% 확률로 1개. 이 시스템은 장비 데이터 구조·드롭 로직·장착 상태를 소유하며, 전투 스탯 적용은 #6 전투 공식이 effective 스탯을 계산할 때 장비 보정치를 포함해 처리한다.

## Player Fantasy

"이 무기 달면 이번 런 더 강해질 수 있다" — 런 시작 전 작은 최적화 결정.

## Detailed Rules

### 장비 데이터 구조 (2026-07-26 리비전 — Resource로 확정, 동료-데이터/적-데이터와 동일 컨벤션)

```gdscript
class_name EquipmentData
extends Resource

@export var id: String
@export var name: String
@export var slot: String   # "weapon" | "armor"
@export var stat: String   # "atk" | "def"
@export var bonus: int     # 고정 보정값
```

**파일 위치 및 로딩 소유권**: `assets/data/equipment/[id].tres`. 로딩·조회는 `EquipmentDatabase`(정적 딕셔너리, id→EquipmentData)가 소유 — 6종 고정이라 `CompanionRegistry`/`EnemyRegistry`처럼 정렬·중복검증이 필요한 동적 로딩은 아니지만, 이름 충돌 방지를 위해 스키마 클래스명(`EquipmentData`)과 조회 테이블명(`EquipmentDatabase`)을 구분한다 (구 버전은 둘 다 `EquipmentData`로 써서 혼동 소지가 있었음).

MVP 장비 목록 (6종):

| ID | 이름 | 슬롯 | 스탯 | 보정값 |
|----|------|------|------|--------|
| `iron_sword` | 철검 | weapon | ATK | +3 |
| `steel_sword` | 강철검 | weapon | ATK | +5 |
| `power_ring` | 힘의 반지 | weapon | **DEF** | +2 |
| `leather_armor` | 가죽 갑옷 | armor | DEF | +3 |
| `chain_mail` | 체인 메일 | armor | DEF | +5 |
| `shield_bracelet` | 방패 팔찌 | armor | DEF | +2 |

**2026-07-26 리비전 — `power_ring`을 ATK에서 DEF로 변경**: 기존에는 무기 슬롯 3종(iron_sword/steel_sword/power_ring)이 전부 ATK 축이라 steel_sword가 항상 다른 둘을 완전히 지배해 실질적 선택지가 없었다(리뷰 지적). `power_ring`을 DEF로 바꾸면 무기 슬롯 자체가 "이 동료를 딜러로 밀지, 좀 더 단단하게 갈지"라는 진짜 트레이드오프를 갖는다 — 새 시스템 없이 테이블 값 하나만 바꾼 수정.

### 장착 상태 (RunManager 내 CompanionRunState에 포함, 2026-07-26 리비전)

```gdscript
# CompanionRunState 확장 필드 (런-상태-관리.md에 추가 필요 — 아직 없음)
var weapon_slot: String = ""    # equipment_id, "" = 빈 슬롯 (null 아님 — GDScript String은 null을 가질 수 없음)
var armor_slot: String = ""     # 동일
```

런 시작 시 #15 파티 구성에서 설정. 런 종료 후 초기화 (장비는 런 간 영속 안 됨 — MVP). **구현 주의**: `""`를 "빈 슬롯" sentinel로 사용 — `동료-데이터.md`의 `unlock_condition_id = ""` 관례와 동일. `EquipmentDatabase.get("")`는 null을 반환하므로 기존 `if weapon and ...` 체크는 `if weapon_slot != "" and ...`로 조건을 명시해야 한다.

### 드롭 로직

```
전투방 클리어 시:
  if randf() < DROP_CHANCE:
    item_id = equipment_pool.pick_random()
    RunManager.inventory.append(item_id)
    emit equipment_dropped(EquipmentData[item_id])
```

MVP 인벤토리: `RunManager`가 보유하는 `Array[String]` (equipment_id 목록). 한도 없음.

### 스탯 보정 적용

이 시스템은 스탯을 직접 수정하지 않는다. 전투 시작 시 또는 조회 시:

```gdscript
func get_effective_atk(companion_state: CompanionRunState) -> int:
    var base := CompanionRegistry.get_by_id(companion_state.companion_id).base_atk
    var weapon := EquipmentDatabase.get(companion_state.weapon_slot) if companion_state.weapon_slot != "" else null
    if companion_state.weapon_slot != "" and weapon == null:
        push_warning("Unknown equipment_id in weapon_slot: [companion_state.weapon_slot]")  # 2026-07-26 추가
    return base + (weapon.bonus if weapon and weapon.stat == "atk" else 0)

func get_effective_def(companion_state: CompanionRunState) -> int:
    var base := CompanionRegistry.get_by_id(companion_state.companion_id).base_def
    var armor := EquipmentDatabase.get(companion_state.armor_slot) if companion_state.armor_slot != "" else null
    if companion_state.armor_slot != "" and armor == null:
        push_warning("Unknown equipment_id in armor_slot: [companion_state.armor_slot]")  # 2026-07-26 추가
    return base + (armor.bonus if armor and armor.stat == "def" else 0)
```

# ponytail: MVP 장비 6종·파티 3명이므로 매 조회 시 계산. 캐시는 장비 수 증가 시 추가.

### Core Rules

1. **슬롯당 1개**: weapon 슬롯에 무기 1개, armor 슬롯에 방어구 1개. 교체 시 기존 장비는 인벤토리로 반환.
2. **런 내 임시 보유**: 장비는 런이 끝나면 사라진다 (영속 장비는 Full Vision).
3. **전투 중 변경 불가**: 장착 변경은 파티 구성 화면에서만.
4. **드롭은 전투방 클리어 후**: 히든방·보스방 드롭 없음 — YAGNI.

## Formulas

**드롭 확률 (2026-07-26 리비전 — rng 주입 명시, 테스트 결정성 확보):**
```
DROP_CHANCE = 0.5
전투방 클리어 후(rng: RandomNumberGenerator 주입받음) rng.randf() < DROP_CHANCE → 드롭 발생
드롭 아이템 = equipment_pool[rng.randi() % equipment_pool.size()]  # 6종 균등, rng 사용 (Array.pick_random()은 전역 RNG라 대신 명시적 인덱싱 사용)
```

**스탯 보정:**
```
effective_atk = base_atk + (weapon.bonus if weapon_slot != "" and weapon.stat == "atk" else 0)
effective_def = base_def + (armor.bonus if armor_slot != "" and armor.stat == "def" else 0)
```

예시: base_atk=10, iron_sword(ATK+3) 장착 → effective_atk=13.

## Edge Cases

- **인벤토리에 같은 장비 2개**: 허용. MVP에서 ID 중복 허용 — 장비 수집이 목적이 아니라 현재 장착이 목적.

- **보스방·히든방 클리어 후 드롭 (2026-07-26 리비전 — #2와의 연동 명시)**: 드롭 없음. 드롭 체크 함수 자체가 `#2 랜덤 던전`이 분류한 전투방(`combat`)에서만 호출되며, 보스방/히든방에서는 호출되지 않는다(no-op이 아니라 애초에 호출되지 않음). Full Vision에서 보스 고유 드롭 추가.

- **장비 없이 전투 시작 (2026-07-26 리비전 — null → "" 정정)**: `weapon_slot = ""`, `armor_slot = ""` → 보정값 0 → 정상 동작.

- **`weapon_slot`/`armor_slot`이 `EquipmentDatabase`에 없는 id를 가리키는 경우 (2026-07-26 추가)**: `push_warning("Unknown equipment_id in [slot]: [id]")` 출력 후 보정값 0으로 처리(정상 진행, 크래시 없음). MVP는 장비에 영속 저장 경로가 없어 발생 가능성이 낮지만, Full Vision에서 장비 영속화 시 `#14 영구 진행`이 겪었던 것과 동일한 클래스의 문제이므로 방어 코드를 지금부터 둔다.

- **동료별 장비 제한**: MVP — 모든 장비가 모든 동료에 장착 가능 (클래스 제한 없음). `#10 동료 데이터`의 `class_type` 태그는 이 시스템에서 사용하지 않는다 — 6종 규모에서는 플레이어가 자연스럽게 역할에 맞는 장비를 고르므로 강제 제한이 불필요하다는 판단(리뷰 확인). Full Vision에서 직업별 장비 제한 추가.

- **슬롯 교체 중 인벤토리 반환**: 동료 A의 weapon_slot="iron_sword" 상태에서 "steel_sword" 장착 → "iron_sword"가 `RunManager.inventory`에 추가되고, "steel_sword"는 인벤토리에서 제거된 뒤 `weapon_slot`에 들어간다. 인벤토리에 중복 아이템 생길 수 있음 (허용).

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 설명 |
|--------|-----------|-----------|------|
| DROP_CHANCE | 50% | 30~70% | 낮으면 장비 희소, 높으면 항상 있음 |
| 무기 ATK 보정 범위 | +2~+5 | +1~+8 | 전투 공식 밸런스와 연동 |
| 방어구 DEF 보정 범위 | +2~+5 | +1~+8 | 동일 |
| MVP 장비 종류 | 6종 | MVP 고정 | 다양성은 Full Vision에서 확장 |

## Acceptance Criteria

1. (드롭 발생, 2026-07-26 리비전 — 주입 rng 명시) GIVEN 전투방 클리어이고 주입된 rng가 DROP_CHANCE 판정을 hit으로 반환하는 상태에서 WHEN 드롭 처리가 실행되면 THEN 장비 풀에서 1개 아이템이 선택되어 RunManager.inventory에 추가되고 `equipment_dropped` 신호가 발신된다.

2. (드롭 미발생, 2026-07-26 리비전 — 주입 rng 명시) GIVEN 전투방 클리어이고 주입된 rng가 DROP_CHANCE 판정을 miss로 반환하는 상태에서 WHEN 드롭 처리가 실행되면 THEN inventory 변화 없이 던전 탐색이 재개된다.

3. (장착 스탯 반영) GIVEN 동료 base_atk=10, weapon_slot="iron_sword"(ATK+3) WHEN `get_effective_atk()` 호출 THEN 13이 반환된다.

4. (슬롯 없음, 2026-07-26 리비전 — null → "" 정정) GIVEN `weapon_slot=""` WHEN `get_effective_atk()` 호출 THEN base_atk 그대로 반환된다.

5. (슬롯 교체, 2026-07-26 리비전 — 제거 검증 추가) GIVEN weapon_slot="iron_sword" 상태에서 WHEN "steel_sword" 장착 THEN weapon_slot이 "steel_sword"로 교체되고, "iron_sword"가 inventory에 추가되며, "steel_sword"는 inventory에서 제거된다.

6. (보스방 드롭 없음) GIVEN 보스방 클리어 WHEN 처리 THEN `equipment_dropped` 신호가 발신되지 않는다 (드롭 체크 함수 자체가 `#2 랜덤 던전`에 의해 호출되지 않음).

7. (히든방 드롭 없음) GIVEN 히든방 진입·처리 완료 WHEN 처리 THEN `equipment_dropped` 신호가 발신되지 않는다 (동일 사유).

8. (알 수 없는 장비 id, 2026-07-26 추가) GIVEN `weapon_slot`이 `EquipmentDatabase`에 없는 id를 가리키는 상태에서 WHEN `get_effective_atk()` 호출 THEN `push_warning`이 기록되고 base_atk 그대로(보정 0) 반환되며 크래시가 발생하지 않는다.
