> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-24

> **Creative Director Review**: Skipped — Lean 모드

## Overview

동료 해금 시스템은 히든방에서 동료를 발견하는 순간의 흐름을 오케스트레이션하는 Feature 레이어 시스템이다. #9 히든 트리거로부터 `companion_discovered(companion_id)` 신호를 수신해, 이번 런 발견 목록(`RunManager.discovered_companions`)에 추가하고 발견 연출 UI를 표시한다. 런 종료 후 #14 영구 진행이 실제 영속 해금을 처리하므로, 이 시스템은 "발견 순간"만 담당한다 — 영속화는 #14 소유.

## Player Fantasy

"○○가 동료가 되었다!" — 카드가 나타나는 순간. 런이 실패해도 이 순간의 발견은 남는다는 확신.

## Detailed Design

### 발견 흐름

```
#9 → companion_discovered(companion_id) 수신
  ↓
이미 discovered_companions에 있으면 즉시 리턴 (중복 방지)
  ↓
RunManager.discovered_companions에 companion_id 추가
  ↓
#10 CompanionData 조회 → 동료 이름·초상화 정보 로드
  ↓
companion_unlocked_this_run(id, name, portrait_path) 신호 발신
  → #20 UI/HUD가 발견 팝업 표시 (블로킹)
  ↓
플레이어 확인(탭) → 팝업 닫기 → 던전 탐색 재개
```

런 종료 시 `RunManager.end_run()` → #14가 `discovered_companions`를 수신해 `unlock_companion()` 호출. 이 시스템은 런 종료 처리에 관여하지 않는다 — #13 RunManager가 자동으로 #14에 위임한다.

### 핵심 API

| 신호/메서드 | 타입 | 설명 |
|-------------|------|------|
| `companion_discovered(id)` | 신호 수신 | #9로부터 수신, 발견 흐름 시작 |
| `companion_unlocked_this_run(id, name, portrait_path)` | 신호 발신 | UI 팝업 표시 트리거 |

### Core Rules

1. **런 내 중복 발견 방지**: `RunManager.discovered_companions`에 이미 있으면 전체 흐름 스킵. 신호 중복 도달에도 안전.
2. **전투 중 발동 없음**: 히든방 진입은 탐색 상태에서만 발생 (#2, #9 보장). 이 시스템은 상태 체크 없음 — 업스트림 보장에 의존.
3. **팝업은 블로킹**: 팝업이 표시된 동안 던전 이동 입력 비활성 (#20 UI/HUD 책임).
4. **런 내 발견 데이터는 RunManager 소유**: 이 시스템은 `RunManager.discovered_companions`에 추가만 하고 직접 보관하지 않는다.

## Edge Cases

- **#10에 companion_id가 없음**: `CompanionData` 조회 실패 → `push_warning("Unknown companion_id in unlock flow: [id]")` + 발견 흐름 중단 (팝업 없음, discovered_companions에도 추가 안 함). 유효하지 않은 동료를 발견한 것으로 처리하지 않는다.

- **팝업 표시 중 앱 백그라운드 전환**: Godot 웹 탭 비활성 시 입력 대기 유지. 재활성화 시 팝업 그대로 표시.

- **런 종료 직전 동료 발견**: 발견 팝업 → 확인 탭 → 던전 재개 흐름 완료 후 런 종료. 팝업 표시 도중 런이 종료되는 경우는 없음 — 전투방에서만 패배 가능하고 히든방에는 전투 없음.

| #9 히든 트리거 | **Hard** | `companion_discovered(id)` 신호 수신 |

| 시스템 | 의존 유형 | 기대 |
|--------|-----------|------|
| #20 UI/HUD | **Hard** | `companion_unlocked_this_run` 신호 수신 → 발견 팝업 표시 |

## Visual/Audio Requirements

이 시스템은 `companion_unlocked_this_run(id, name, portrait_path)` 신호를 발신한다.
- 팝업 레이아웃·애니메이션: #20 UI/HUD 소유
- 발견 SFX/BGM: #21 오디오 구독

## UI Requirements

이 시스템은 UI를 소유하지 않는다. 팝업은 `#20 UI/HUD` 소유:
- 동료 초상화 (CompanionData.portrait_path)
- 동료 이름 (CompanionData.name)
- "동료가 되었다!" 텍스트
- 확인 버튼 (탭)

## Acceptance Criteria

1. (발견 목록 추가) GIVEN `companion_discovered("hidden_archer_03")` 수신 WHEN 처리되면 THEN `RunManager.discovered_companions`에 `"hidden_archer_03"`이 추가된다.

2. (팝업 트리거) GIVEN `companion_discovered` 수신 WHEN #10에서 데이터 조회 성공 THEN `companion_unlocked_this_run` 신호가 발신되고 UI 팝업이 표시된다.

3. (중복 방지) GIVEN `discovered_companions = ["hidden_archer_03"]`인 상태 WHEN `companion_discovered("hidden_archer_03")`가 다시 수신되면 THEN `discovered_companions`에 중복 추가되지 않고 팝업이 재표시되지 않는다.

4. (유효하지 않은 ID) GIVEN 존재하지 않는 companion_id 수신 WHEN 처리되면 THEN `push_warning`이 기록되고 `discovered_companions`에 추가되지 않으며 팝업이 표시되지 않는다.

5. (런 종료 후 영속) GIVEN 런 중 `discovered_companions = ["hidden_archer_03"]` WHEN 런이 종료되면 THEN #14 `unlock_companion("hidden_archer_03")`이 호출되어 영구 해금된다 (#13 런 상태 관리 보장).

6. (팝업 블로킹) GIVEN 발견 팝업이 표시된 상태 WHEN 던전 이동 버튼 탭 THEN 버튼이 비활성 상태로 무시된다 (#20 UI/HUD 보장).
