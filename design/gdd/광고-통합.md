## Overview

광고 통합 시스템은 웹 브라우저 환경에서 광고 SDK를 연동하고 노출 타이밍을 결정하는 Polish 레이어 시스템이다. #19 씬 관리의 씬 전환 흐름에 진입해 적절한 시점에 인터스티셜 광고를 삽입한다. MVP 타이밍: 런 결과 화면 → 메인메뉴 전환 시 1회. Godot 웹 내보내기(HTML5) 환경에서 `JavaScriptBridge`를 통해 광고 SDK를 호출한다. 게임플레이 중에는 광고 없음 — 전환 시점에만.

## Player Fantasy

(플레이어 대상 아님) — 광고가 게임플레이를 끊지 않는다는 것이 플레이어 경험 목표. 전환 시점의 1회 삽입으로 수익화와 경험 최소화를 동시에 달성한다.

### 구현 구조 (Godot 4.6 웹 내보내기)

```gdscript
# AdManager Autoload (최소 구현)
extends Node

const AD_TIMEOUT_MS := 5000
var _pending_callback: Callable
var _timeout_timer: SceneTreeTimer
var _js_bridge = JavaScriptBridge  # 2026-07-26 추가 — 테스트에서 mock으로 교체 가능한 주입 지점 (아래 AC1/AC6 참조)

func _ready() -> void:
    # 2026-07-26 추가 — 버그 수정: 구 버전은 JS의 GodotAdBridge.adCompleted() 호출을
    # 받을 실제 바인딩이 없어 window.GodotAdBridge가 undefined였고, 두 분기 모두
    # ReferenceError로 죽어 5초 타임아웃만 실제로 동작하는 경로였다.
    if OS.has_feature("web"):
        _js_bridge.eval("window.GodotAdBridge = {};", true)
        var bridge = _js_bridge.get_interface("window").GodotAdBridge
        bridge.adCompleted = _js_bridge.create_callback(_on_ad_completed)

func show_interstitial(on_complete: Callable) -> void:
    if not OS.has_feature("web"):
        on_complete.call()
        return

    if _pending_callback:  # 2026-07-26 추가 — 재진입 가드 (버그 수정, 아래 참조)
        return

    _pending_callback = on_complete
    _timeout_timer = get_tree().create_timer(AD_TIMEOUT_MS / 1000.0)
    _timeout_timer.timeout.connect(_on_ad_timeout)

    _js_bridge.eval("""
        if (window.adManager && window.adManager.showInterstitial) {
            window.adManager.showInterstitial();
        } else {
            GodotAdBridge.adCompleted();
        }
    """)

func _on_ad_completed() -> void:  # JS에서 GodotAdBridge.adCompleted() 호출 시
    if _timeout_timer:
        _timeout_timer.timeout.disconnect(_on_ad_timeout)
    _fire_callback()

func _on_ad_timeout() -> void:
    _fire_callback()

func _fire_callback() -> void:
    if _pending_callback:
        _pending_callback.call()
        _pending_callback = Callable()
```

# ponytail: JS 브릿지 바인딩 상세는 /create-architecture에서 확정. GodotAdBridge 네이밍은 임시.

**2026-07-26 리비전 — 버그 수정 2건:**
1. **JS→GDScript 콜백 배선 누락**: 구 버전은 `GodotAdBridge.adCompleted()`를 호출만 했지 `window.GodotAdBridge`를 만들거나 `_on_ad_completed`에 바인딩하는 코드가 전혀 없었다. 실제로는 `GodotAdBridge`가 `window`에 존재하지 않아 두 JS 분기(정상 완료·SDK 미로드) 모두 `ReferenceError`로 죽고, 5초 타임아웃 경로만 우연히 동작했다. `_ready()`에서 `JavaScriptBridge.create_callback()`으로 실제 콜백을 등록하도록 수정.
2. **재진입 시 타이머 누수**: 이전 호출의 `_timeout_timer`가 아직 대기 중인 상태에서 `show_interstitial()`이 다시 호출되면, 새 타이머로 덮어써지면서 이전 타이머는 연결이 끊기지 않은 채 자신의 원래 스케줄대로 계속 살아있어 엉뚱한 시점에 새 콜백을 강제 발화시킬 수 있었다. `_pending_callback`이 이미 있으면 재호출을 무시하는 가드를 추가해 해결 — 이 가드는 동시에 Edge Case의 "메인메뉴로 버튼 2회 탭" 상황도 `#20`에 대한 의존 없이 이 시스템 자체적으로 방지한다 (아래 Edge Cases 참조).

### 씬 전환 연동

```
RunResult "메인메뉴로" 버튼 탭
  ↓
AdManager.show_interstitial(func(): SceneManager.go_to(S-02, FADE))
  ↓
광고 표시 (브라우저 오버레이)
  ↓
광고 종료 or 스킵 → on_complete 콜백 → SceneManager.go_to(S-02, FADE)
  또는
5초 타임아웃 → on_complete 강제 콜백 → SceneManager.go_to(S-02, FADE)
```

### Core Rules

1. **게임플레이 중 광고 없음**: 전투 중·던전 탐색 중 광고 호출 없음.
2. **비웹 환경 즉시 콜백**: `OS.has_feature("web") == false` → on_complete 즉시 호출. 에디터/데스크톱 개발에 영향 없음.
3. **타임아웃 페일세이프**: 5초 내 응답 없으면 강제 콜백. 광고 SDK 오류가 씬 전환을 영구 블록하지 않음.
4. **빈도 제한**: MVP — 런당 최대 1회 (런 종료 시). SDK 자체 빈도 제한에도 의존.

## Formulas

수치 공식 없음.

**광고 타임아웃:**
```
AD_TIMEOUT_MS = 5000
show_interstitial() 호출 후 5000ms 내 _on_ad_completed() 미수신
  → _on_ad_timeout() 강제 콜백
```

## Edge Cases

- **광고 SDK 미로드**: `window.adManager` undefined → JS eval 조건 분기에서 `GodotAdBridge.adCompleted()` 즉시 호출 → 타임아웃 없이 씬 전환.

- **광고 표시 중 탭 비활성**: 광고 SDK가 탭 재활성화 시 재개 또는 스킵. GDScript 레이어에서 추가 처리 없음 — SDK 의존.

- **에디터 환경**: `OS.has_feature("web") == false` → 즉시 콜백. 개발·테스트에 영향 없음.

- **연속 런 (광고 반복)**: 각 런 종료마다 show_interstitial() 호출. SDK 자체 빈도 제한이 실제 노출 수 조절.

- **_pending_callback이 이미 있는 상태에서 재호출** (2026-07-26 리비전 — 소유권 정정): `show_interstitial()` 자체의 재진입 가드가 재호출을 무시한다 (위 코드 참조). 구 버전은 이를 "`#20 UI/HUD`가 버튼 비활성으로 방지"라고 명시했으나, `#20 UI/HUD` 문서 어디에도 이 화면·이 버튼에 대한 그런 보장이 없고 `#18`의 Upstream Dependencies에도 `#20`이 등재되어 있지 않았다 — 검증되지 않은 타 시스템 의존을 전제한 것. 이제 이 시스템 자체가 방어하므로 `#20`의 실제 구현과 무관하게 안전하다.

## Acceptance Criteria

(2026-07-26 리비전 — AC1/AC6은 실제 브라우저 JS 실행을 요구해 GUT/헤드리스 환경에서 검증 불가능했다. `_js_bridge` 주입 지점을 mock으로 교체해 GDScript 쪽에서 관찰 가능한 계약만 검증하도록 재기술.)

1. (웹 환경 광고 호출) GIVEN 웹 빌드에서 RunResult "메인메뉴로" 탭, `_js_bridge`가 mock으로 주입된 상태 WHEN `AdManager.show_interstitial()` 호출 THEN mock의 `eval()`이 `showInterstitial`을 포함한 문자열 인자로 정확히 1회 호출된다.

2. (비웹 환경 즉시 콜백) GIVEN 에디터/데스크톱 환경 WHEN show_interstitial() 호출 THEN 광고 없이 즉시 on_complete 콜백이 실행된다.

3. (광고 완료 후 씬 전환) GIVEN 광고 표시 완료 WHEN mock을 통해 `_on_ad_completed()`가 직접 호출됨(JS 콜백 수신 시뮬레이션) THEN on_complete 콜백 실행 → SceneManager.go_to(S-02, FADE).

4. (타임아웃 페일세이프) GIVEN 광고 SDK가 5000ms 내 응답 없음 WHEN 타임아웃 발생 THEN on_complete 강제 콜백 → 씬 전환 진행.

5. (게임플레이 중 광고 없음) GIVEN 전투 중 또는 던전 탐색 중 WHEN 상태 확인 THEN show_interstitial()가 호출되지 않는다. (`#1`/`#15`가 AdManager를 호출하지 않는다는 보장 자체는 각 시스템 소관 — 이 AC는 `#18`이 그런 상황에서 스스로 광고를 트리거하지 않음만 검증한다.)

6. (SDK 미로드 처리) GIVEN mock `_js_bridge`가 `window.adManager`를 undefined로 시뮬레이션 WHEN show_interstitial() 호출 THEN eval 인자 문자열의 조건 분기가 `GodotAdBridge.adCompleted()`를 즉시 타도록 구성되며, 타임아웃 없이 (mock을 통해 시뮬레이션된) 콜백 수신 시 씬 전환이 진행된다.

7. (재진입 가드, 2026-07-26 추가) GIVEN `show_interstitial()`이 호출되어 `_pending_callback`이 아직 비어있지 않은 상태에서 WHEN `show_interstitial()`이 다시 호출되면 THEN 두 번째 호출은 즉시 반환되고 `_timeout_timer`가 새로 생성되지 않으며 첫 번째 콜백만 유효하게 유지된다.
