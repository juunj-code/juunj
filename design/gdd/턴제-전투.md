# 턴제 전투 (Turn-based Combat)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-24
> **Implements Pillar**: 전략은 단순하게, 조합은 깊게
> **Creative Director Review**: Skipped — Lean 모드

## Overview

턴제 전투 시스템은 바람의 탑의 전투 흐름 전체를 오케스트레이션하는 Feature 레이어 시스템이다. 전투 시작 시 #13 런 상태 관리에서 파티·적 상태를 받아, #6 전투 공식이 정한 턴 순서대로 각 유닛의 행동을 진행한다. 플레이어 턴에는 액션·타겟 입력을 받고, 적 턴에는 #7 적 AI에 결정을 위임한다. 데미지 계산은 #6 전투 공식, 상태이상 처리는 #12 상태이상, 결과 저장은 #13 런 상태 관리에 각각 위임한다. 이 시스템은 "게임플레이 수치"를 계산하지 않는다 — 순서를 정하고, 입력을 받고, 결과를 분배하는 지휘자 역할이다.

## Player Fantasy

"이번 턴에 기절 거는 게 맞나, 아니면 독 걸린 애 먼저 처리하는 게 맞나?"

전투는 빠르게 진행돼야 하지만, 각 선택에 무게감이 있어야 한다. 한 턴이 15~30초 안에 끝나고, 전투 하나는 3~5분 내에 마무리된다. 복잡한 메뉴 탐색 없이 탭 두 번(액션 선택 → 타겟 선택)으로 입력이 완료된다.

## Detailed Rules

### 전투 흐름

```
전투 시작
  ↓
턴 순서 계산 (#6 공식 ③)
  ↓
[턴 루프]
  현재 유닛 턴 시작
    → #12: DOT 틱 + 지속시간 감소 + 만료 제거
    → 전투 종료 체크 (#6 공식 ⑤) — DOT 즉사 포함
    → SKIP_TURN 여부 확인
        YES: 턴 스킵 → 다음 유닛
        NO:
          플레이어 유닛: 입력 대기 (액션 + 타겟)
          적 유닛: #7 AI에 결정 위임 — `decide_action(enemy, alive_companions, targeted_this_turn)` 호출. `targeted_this_turn`은 이 시스템(#1)이 라운드 시작 시 빈 배열로 초기화해 소유하는 상태이며(#7 적 AI의 타겟 분산 규칙이 사용), 적 유닛이 타겟을 결정할 때마다 이 시스템이 해당 타겟을 배열에 추가한다.
    → 액션 실행 (데미지: #6 공식 ①②, 효과: #12 apply_effect)
    → 전투 종료 체크
    → SP 회복 (#6 공식 ④: sp += SP_GAIN_PER_TURN)
    → 다음 유닛
  [모든 유닛 턴 완료 → 새 라운드: 턴 순서 재계산, `targeted_this_turn` 초기화]
  ↓
전투 종료 → #13 결과 전달 → #19 씬 전환
```

### 플레이어 입력 프로토콜 (터치 우선)

| 단계 | UI 요소 | 입력 |
|------|---------|------|
| 1. 액션 선택 | 하단 버튼: [기본 공격] [스킬 (SP 부족 시 비활성)] | 탭 |
| 2. 타겟 선택 | 적 유닛 위 선택 하이라이트 | 탭 |
| 3. 확인 | 자동 실행 (타겟 선택 즉시) | — |

취소: 타겟 선택 전에 다른 액션 버튼 탭 → 액션 재선택. 타겟 선택 후 취소 없음 — 빠른 템포 유지.

### 전투 시작 조건

- `RunManager.state == "EXPLORING"` + 전투 방 진입
- `RunManager.start_combat(enemy_list)` 호출 → `current_enemies` 초기화, `state = "IN_COMBAT"`
- `SceneManager.go_to(S-05, FADE)`

### 전투 종료 조건

| 결과 | 조건 | 처리 |
|------|------|------|
| 승리 | `all(e.current_hp <= 0 for e in current_enemies)` | `RunManager.end_combat(victory=true)` |
| 패배 | `all(c.current_hp <= 0 for c in party)` | `RunManager.end_run(success=false)` |
| 동시 | 승리 우선 | 동일 |

### Core Rules

1. **입력 없이 진행 없음**: 플레이어 턴에서 입력 없으면 전투 대기 — 타임아웃 없음 (턴제).
2. **턴 순서는 매 라운드 재계산**: 버프로 speed가 변하면 다음 라운드 순서가 바뀐다.
3. **SP 회복은 턴 종료 후**: 행동 완료 후 SP 회복. 해당 턴에 스킬 쓰고 같은 턴에 또 회복되는 구조 아님.
4. **전투 중 씬 전환 없음**: 히든 동료 발견 연출 등 모든 인터럽트는 전투 종료 후 처리.

## Formulas

이 시스템은 공식을 직접 소유하지 않는다. 모두 #6 전투 공식에 위임.

| 연산 | 위임 대상 |
|------|-----------|
| 데미지 계산 | #6 공식 ① (기본) / ② (스킬) |
| 턴 순서 | #6 공식 ③ |
| SP 회복 | #6 공식 ④ |
| 전투 종료 판정 | #6 공식 ⑤ |
| 스탯 수정치 | #12 `get_modified_stats()` |

## Edge Cases

- **파티 전원 기절(SKIP_TURN) 상태**: 기절은 1턴 — 다음 라운드 정상 행동. 모두 기절 중인 라운드는 전체 스킵, 전투 진행 불가 상태 아님.

- **적이 이미 처치된 후 다른 적의 DOT 피해**: 처치 판정은 즉시 발생. 이미 `current_hp=0`인 유닛은 DOT 처리 대상에서 제외.

- **스킬 선택 후 SP가 cost 미만인 경우** (버그): UI가 비활성화로 방지. 만약 호출되면 기본 공격으로 대체 + `push_warning`.

- **전투 중 앱 백그라운드 전환**: 입력 대기 상태 유지 (Godot 웹 탭 비활성 시 로직 일시 정지). 재활성화 시 입력 대기 화면 그대로 복귀.

이 시스템은 전투 이벤트 신호를 발신한다. 실제 연출은 외부 담당:
- 피격 애니메이션, 스킬 이펙트: `#1 턴제 전투` 신호 → `#20 UI/HUD` 또는 별도 VFX 노드
- SFX: `#21 오디오` 구독
- 동료 발견 플래시: 전투 종료 후 `#3 동료 해금`이 처리

## UI Requirements

전투 중 필요한 UI (모두 `#20 UI/HUD` 소유):
1. **파티 HP/SP 바** — 실시간 갱신
2. **적 HP 바** — 보스는 별도 보스 HP 바
3. **액션 버튼** — [기본 공격] [스킬명 (SP 비용)] — SP 부족 시 비활성
4. **타겟 선택 하이라이트** — 탭 가능한 적 유닛 위 표시
5. **상태이상 아이콘** — 각 유닛 옆 아이콘·잔여 턴
6. **현재 턴 표시** — 누구의 턴인지 (플레이어/적)

📌 **UX Flag**: 터치 최소 44×44px 보장, 타겟 선택과 액션 선택을 한 화면에서 처리하는 레이아웃은 `/ux-design`에서 확정.

## Acceptance Criteria

1. (턴 순서) GIVEN 속도 [9,8,6,8,6]인 유닛 5개 WHEN 전투 시작 시 THEN 동료 우선 타이브레이크 적용 후 올바른 순서로 진행된다.

2. (플레이어 입력) GIVEN 플레이어 동료 턴 WHEN 기본 공격 + 적 타겟 선택 THEN 데미지가 계산·적용되고 해당 적 HP가 감소한다.

3. (스킬 SP 체크) GIVEN SP=1, cost_sp=2인 스킬이 있는 턴 WHEN 스킬 버튼 표시 THEN 버튼이 비활성화되어 있다.

4. (적 AI 위임) GIVEN 적 유닛 턴 WHEN AI가 호출되면 THEN #7 AI가 반환한 (액션, 타겟)으로 자동 실행되고 플레이어 입력 없이 진행된다.

5. (DOT 즉사 → 전투 종료) GIVEN 마지막 적 HP=3이고 poison(5)이 활성인 상태에서 WHEN 해당 적 턴 DOT 틱이 실행되면 THEN 전투 종료(승리)가 즉시 판정된다.

6. (동시 종료 → 승리 우선) GIVEN 마지막 적의 반격으로 마지막 동료 HP=0이 되는 동시에 전투가 종료될 때 WHEN 판정 THEN 승리 처리된다.

7. (SP 회복 타이밍) GIVEN sp=1, cost_sp=2인 유닛이 기본 공격 후 WHEN 턴 종료 시 THEN sp=2가 되어 다음 턴에 스킬 사용 가능하다.

8. (패배) GIVEN 모든 동료 current_hp=0 WHEN 판정 THEN RunManager.end_run(success=false)가 호출된다.
