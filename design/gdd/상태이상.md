# 상태이상 (Status Effects)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-26
> **Implements Pillar**: 전략은 단순하게, 조합은 깊게
> **Creative Director Review**: Skipped — Lean 모드

## Overview

상태이상 시스템은 전투 중 동료·적에게 일시적으로 적용되는 버프·디버프 효과를 정의하고 처리하는 Core 레이어 시스템이다. SkillData의 `effect_id` 필드가 참조하는 상태이상 블루프린트를 소유하고, 턴 시작 시 활성 효과를 처리(틱·지속시간 차감·만료 제거)하며, #6 전투 공식에 수정된 ATK·DEF 값을 제공한다. 이 시스템은 "어떤 스킬이 효과를 발동하는지" 모른다 — #1 턴제 전투가 스킬 효과 적용을 호출하면 처리할 뿐이다. MVP는 3종 상태이상(독·기절·방어 강화)으로 확정하며, 스킬 조합의 전략적 깊이를 최소 코드로 실현한다.

## Player Fantasy

"독 걸린 보스에게 기절까지 먹이면..." — 단 두 개의 효과 조합이 만드는 전략적 흥분.

- 독(DoT)은 "이번 턴 안 죽어도 다음 턴에 죽는다"는 압박을 적에게 준다. 플레이어가 턴을 낭비하지 않고 다른 적부터 처리하는 전략적 결정의 근거가 된다.
- 기절은 "이 턴 보스 스킬 막았다"는 통제감. 가장 위험한 순간에 개입할 수 있다는 안도.
- 방어 강화는 "탱커 동료 버프 → 보스 집중 유도"라는 파티 시너지의 씨앗.

## Detailed Rules

### MVP 상태이상 카탈로그

| ID | 이름 | 타입 | 값 | 지속 | 적용 대상 | 설명 |
|----|------|------|-----|------|-----------|------|
| `poison` | 독 | `DOT` | 5 (고정 데미지/턴) | 3턴 | 동료·적 모두 | 턴 시작 시 5 데미지. 방어력 무시. |
| `stun` | 기절 | `SKIP_TURN` | — | 1턴 | 동료·적 모두 | 해당 턴 행동 불가. 아무것도 안 함. |
| `defense_up` | 방어 강화 | `STAT_MODIFY` (DEF +8) | +8 | 2턴 | 동료·적 모두 | DEF에 +8 수정치 적용. |

### StatusEffect 스키마

```gdscript
class_name StatusEffect
extends Resource

@export var id: String           # "poison", "stun", "defense_up"
@export var name: String         # 표시 이름
@export var type: String         # "DOT" | "SKIP_TURN" | "STAT_MODIFY"
@export var value: int = 0       # DOT: 데미지량 / STAT_MODIFY: 수정치 / SKIP_TURN: 미사용
@export var stat_target: String  # STAT_MODIFY 전용: "atk" | "def" ("" otherwise)
@export var duration: int        # 남은 지속 턴 수 (런타임 카피에서 감소)
```

**파일 위치:** `assets/data/status_effects/[id].tres`

### 상태이상 처리 흐름 (매 유닛 턴)

```
턴 시작
  ↓
1. DOT 틱: active_effects 중 type==DOT → 데미지 적용 (방어력 무시, min 1)
2. SKIP_TURN 체크: type==SKIP_TURN → 해당 유닛 이번 턴 액션 스킵
3. 지속시간 감소: 모든 active_effects의 duration -= 1
4. 만료 제거: duration <= 0 → active_effects에서 제거
  ↓
5. STAT_MODIFY 적용: #6 전투 공식 호출 시, active_effects 중 STAT_MODIFY를
   읽어 modified_atk / modified_def 계산 후 전달
```

### 스탯 수정 계산

```
modified_atk = base_atk + sum(e.value for e in active_effects if e.type=="STAT_MODIFY" and e.stat_target=="atk")
modified_def = base_def + sum(e.value for e in active_effects if e.type=="STAT_MODIFY" and e.stat_target=="def")
```

음수 수정치 허용 — DEF 디버프 확장 시 사용 (MVP는 defense_up만 있으므로 음수 없음). #6 전투 공식은 `max(0, modified_def)` 클램핑 없이 수신 — 클램핑은 **이 시스템** 책임:

```
modified_def = max(0, modified_def)   # 이 시스템에서 클램핑 후 전달
modified_atk = max(0, modified_atk)
```

### Core Rules

1. **런타임 카피 원칙**: StatusEffect 리소스는 블루프린트. 적용 시 `duration`을 복사한 인스턴스를 `#13 런 상태 관리`에 저장 — 원본 리소스 변경 없음. **구현 필수 (2026-07-26 리비전)**: `apply_effect()`는 반드시 `effect_resource.duplicate()`로 새 인스턴스를 생성한 뒤 저장해야 한다 — 참조 대입(`var instance = effect_resource`)을 쓰면 Godot의 리소스 캐싱 때문에 같은 `poison.tres`를 적용받은 모든 유닛이 동일 인스턴스를 공유하게 되어, 한 유닛의 지속시간 감소가 다른 유닛(및 원본 블루프린트)에 그대로 전파된다.
2. **중복 적용 정책**: 같은 `id` 효과가 이미 활성 중이면 기존 효과를 **교체** (duration 리셋). 스택 없음 — 독을 두 번 걸어도 독은 1개, 타이머만 초기화.
3. **DOT는 방어력 무시**: `max(1, poison.value)` 직접 적용 — `def` 빼지 않음. 방어형 적/동료에도 독이 의미 있도록.
4. **만료는 턴 시작 처리 후**: 기절 유닛은 이번 턴 행동 안 함 → 지속시간 감소 → 다음 턴에는 행동 가능.

## Formulas

**① DOT 데미지 (방어 무시)**
```
dot_damage = max(1, effect.value)   # 현재 POISON_DAMAGE = 5
```

**② 스탯 수정 (STAT_MODIFY 합산)**
```
modified_stat = max(0, base_stat + Σ(e.value for matching active effects))
```

**③ 지속시간 감소**
```
effect.duration -= 1   (매 턴 시작, DOT 틱 처리 후)
if effect.duration <= 0: remove from active_effects
```

**MVP 상태이상 수치 설계 근거:**

| 효과 | 값 | 지속 | 설계 근거 |
|------|----|------|-----------|
| 독 데미지 | 5/턴 | 3턴 | 총 15 데미지. 최약 동료(60HP)의 25%. 위협이지만 즉사 없음. 보스(150~300HP)에 15는 경미 — 독은 일반 적 처리용 |
| 기절 | — | 1턴 | 보스 스킬 1회 차단. 2턴 이상이면 보스전 trivial화 |
| 방어 강화 | +8 DEF | 2턴 | 동료 최약 DEF(5)+8=13. 보스의 실제 위협인 강 스킬 기준(`#11 적-데이터` 앵커: `floor(25×1.4)−5=30`)으로 계산하면 `floor(25×1.4)−13=22` — 앵커 기준 30 데미지를 22로, 27% 경감. (2026-07-26 리비전: 기존 "25−13=12"는 기본 공격 공식을 써서 실제 위협인 보스 스킬 대비 경감 효과를 과장했었음 — #10/#11/#6/#7 리뷰에서 반복 확인된 동일 유형의 오류) |

## Edge Cases

- **기절 중 DOT 동시 적용**: DOT 틱은 기절과 무관하게 처리 → 기절 유닛도 독 데미지는 받음. 순서: DOT 먼저, 이후 SKIP_TURN 체크.

- **독 데미지로 HP가 0이 된 경우**: 전투 종료 조건(#6)을 즉시 체크. 유닛이 DOT로 사망 가능 — #1 턴제 전투가 DOT 처리 후 전투 종료 체크 호출해야 함.

- **기절 유닛에게 중복 기절 적용**: 교체 정책(Core Rule 2)으로 duration 1로 리셋. 사실상 1턴 연장 효과 — 의도된 동작.

- **defense_up 중 추가 defense_up 적용**: 교체 정책 → 기존 효과 만료 전에 duration 2로 리셋. 수치는 합산되지 않음 (스택 없음). "+16 DEF"는 MVP 범위 밖.

- **STAT_MODIFY 수정치가 클램핑 후 0 미만이 되는 경우**: MVP에는 DEF 디버프 없으므로 발생 안 함. 미래 확장 시 `max(0, ...)` 이 시스템에서 보장.

- **전투 종료 시 상태이상 잔존**: #13 런 상태 관리가 전투 종료 시 active_effects 초기화. 다음 전투는 클린 상태로 시작.

- **아군이 걸어준 버프 vs 자가 시전 버프의 지속시간 비대칭 (2026-07-26 리비전 — 리뷰에서 발견)**: 턴 순서상 지원형 동료가 탱커보다 먼저 행동해 `defense_up`을 걸어주면, 탱커의 턴 시작 처리(지속시간 감소 단계)가 같은 라운드 안에서 곧바로 실행되어 duration이 2→1로 즉시 한 번 깎인다. 반면 탱커가 스스로에게 같은 스킬을 쓰면 자신의 지속시간 감소 단계는 이미 지나간 뒤라 duration=2를 온전히 받는다. 즉 "누가 언제 걸어주느냐"에 따라 실질 지속시간이 1턴 차이 날 수 있다 — 버그가 아니라 턴 순서 기반 시스템의 자연스러운 결과이므로 별도 보정은 하지 않되, 이 비대칭은 문서화된 의도로 취급한다.

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 너무 낮을 때 | 너무 높을 때 |
|--------|-----------|-----------|-------------|-------------|
| `POISON_DAMAGE` | 5/턴 | 3 ~ 8 | 독 존재감 없음 | 일반 적 사망 가속 → 전투 너무 짧음 |
| 독 `duration` | 3턴 | 2 ~ 4 | 총 데미지 미미 | 전투보다 독으로 처리 → 전략 단순화 |
| 기절 `duration` | 1턴 | 1 (고정 권장) | — | 2턴이면 보스전 trivial |
| `DEFENSE_UP_VALUE` | +8 DEF | 5 ~ 12 | 탱킹 효과 미미 | 보스 ATK 완전 무효화 |
| defense_up `duration` | 2턴 | 2 ~ 3 | 사용 타이밍 좁음 | 영구 버프에 가까워짐 |

## Acceptance Criteria

1. (독 – 기본) GIVEN 유닛에게 `poison` 효과가 적용된 상태에서 WHEN 턴이 시작되면 THEN 해당 유닛이 5 데미지를 받고(방어력 무시), duration이 3→2로 감소한다.

2. (독 – 만료) GIVEN 유닛에게 `poison`이 적용되고 3턴이 경과한 상태에서 WHEN 3번째 틱 처리 후 THEN duration=0으로 active_effects에서 제거된다.

3. (독 – DOT 즉사) GIVEN 유닛 HP=3이고 `poison`(value=5)이 활성인 상태에서 WHEN 턴 시작 DOT 틱이 처리되면 THEN HP=0이 된다. (그 이후 `#1 턴제 전투`가 전투 종료를 체크하는지는 `#1`의 AC 범위이며, 이 시스템은 HP를 0으로 만드는 것까지만 보증한다.)

4. (기절 – 행동 스킵) GIVEN 유닛에게 `stun` 효과가 적용된 상태에서 WHEN 해당 유닛의 턴이 되면 THEN 유닛은 어떤 액션도 실행하지 않고 턴을 넘긴다.

5. (기절 – 1턴 후 만료) GIVEN `stun` duration=1이 적용된 상태에서 WHEN 해당 턴 처리가 완료되면 THEN duration=0으로 제거되고 다음 턴에는 정상 행동한다.

6. (방어 강화 – 스탯 수정) GIVEN 동료 base_def=5에 `defense_up`(value=+8)이 활성인 상태에서 WHEN #6 전투 공식에 def 값을 제공하면 THEN modified_def=13이 전달된다.

7. (중복 적용 – 교체) GIVEN 유닛에게 `poison`(duration=2)이 활성인 상태에서 WHEN 동일 `poison` 효과를 다시 적용하면 THEN active_effects의 `poison`은 1개이고 duration=3으로 리셋된다.

8. (스탯 클램핑) GIVEN 수정 후 modified_def가 음수가 되는 경우 WHEN 이 시스템이 값을 반환하면 THEN 반환값은 0이고 음수가 아니다.

9. (전투 종료 후 초기화) GIVEN 전투가 종료된 직후 WHEN #13 런 상태 관리가 active_effects를 초기화하면 THEN 다음 전투 시작 시 모든 유닛의 active_effects는 비어 있다.

10. (기절 + DOT 동시) GIVEN 유닛에게 `stun`과 `poison` 양쪽이 활성인 상태에서 WHEN 해당 유닛의 턴이 시작되면 THEN DOT 틱(5 데미지)이 먼저 처리되고 이후 행동이 스킵된다.

11. (런타임 카피 검증, 2026-07-26 추가) GIVEN 동일한 `poison` 블루프린트(.tres, duration=3)를 유닛 A와 유닛 B에게 각각 적용한 상태에서 WHEN A의 인스턴스만 1턴 경과해 duration이 3→2로 감소하면 THEN B의 인스턴스는 duration=3을 그대로 유지하고, 원본 `.tres` 블루프린트의 duration 필드도 3으로 변하지 않는다.
