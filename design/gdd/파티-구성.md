## Overview

파티 구성 시스템은 런 시작 전 플레이어가 파티를 편성하는 화면을 오케스트레이션하는 Feature 레이어 시스템이다. #14 영구 진행에서 해금된 동료 목록을 가져와 선택 UI를 제공하고, #4 장비 인벤토리를 조회해 장착 UI를 제공한다. 플레이어가 파티를 확정하면 #13 RunManager에 `start_run(party_config)`를 호출해 런 초기화를 트리거한다. 이 시스템은 선택 흐름을 오케스트레이션하며, 데이터 저장과 런 초기화는 각각 #14·#13에 위임한다.

## Player Fantasy

"이번엔 어떤 조합으로 갈까?" — 해금된 동료들을 보며 느끼는 빌드 구성의 기대감.

## Detailed Rules

### 화면 흐름

```
MainMenu → "런 시작" 탭
  ↓
PartySelectScreen (S-03) 표시
  ├─ 해금 동료 카드 그리드 (ProgressManager.get_unlocked_companions())
  ├─ 파티 슬롯 3개 (선택된 동료 표시)
  └─ 장비 패널 (선택된 동료별 weapon/armor 슬롯 + 인벤토리)
  ↓
"출발" 버튼 탭 (파티 1명 이상 시 활성)
  ↓
RunManager.start_run(party_config) 호출
  ↓
SceneManager.go_to(S-04 DungeonExploration, FADE)
```

### 파티 제약

| 항목 | 규칙 |
|------|------|
| 최소 파티 | 1명 |
| 최대 파티 | 3명 |
| 같은 동료 중복 | 불가 |
| 장비 장착 | 선택 사항 — 미장착으로 출발 가능 |

### party_config 구조

```gdscript
# RunManager.start_run(party_config)에 전달
[
  {
    "companion_id": "warrior_base_01",
    "weapon_slot": "iron_sword",   # "" = 미장착 (2026-07-26 리비전 — null 아님, #4/#13과 동일한 sentinel 컨벤션)
    "armor_slot": ""
  },
  {
    "companion_id": "hidden_archer_03",
    "weapon_slot": "",
    "armor_slot": "leather_armor"
  }
]
```

### 초기 상태

- 게임 첫 런 (해금 동료 = 기본 동료 1명만): 기본 동료가 파티 슬롯 1번에 자동 배치. "출발" 즉시 활성.
- 이전 런 인벤토리는 존재하지 않음 (런 종료 시 초기화). 장비 패널 비어있는 상태로 시작.

### Core Rules

1. **해금된 동료만 표시**: `ProgressManager.get_unlocked_companions()`에서 반환된 ID만 선택 가능.
2. **최소 1명**: 파티 슬롯이 모두 비어있으면 "출발" 버튼 비활성.
3. **장비는 런 전용**: 이 화면에서 장착한 장비는 이번 런에만 유효. 다음 런 시작 시 초기화.
4. **이전 선택 미유지**: 파티 구성 화면 진입 시 항상 초기화 (MVP — 편의성은 Full Vision). (2026-07-26 리비전 — 명확화: 해금 동료가 1명뿐이라 자동 배치된 경우도 이 규칙을 따른다 — 화면을 나갔다 재진입해도 매번 다시 자동 배치되며, "이전 선택을 기억해서" 유지되는 것이 아니다.)
5. **빈 슬롯은 `""`**: 미장착 weapon_slot/armor_slot은 `null`이 아닌 빈 문자열 `""`로 표현 (2026-07-26 추가 — `#4 장비`/`#13 런 상태 관리`와 동일한 sentinel 컨벤션. GDScript의 typed String은 null을 가질 수 없음).

## Formulas

수치 공식 없음. UI 활성화 조건:

```
"출발" 버튼 활성 = len(selected_party) >= 1
동료 카드 선택 가능 = id in unlocked_companions AND id not in selected_party
추가 선택 가능 = len(selected_party) < 3
```

## Edge Cases

- **해금 동료 1명 (기본 동료만)**: 기본 동료 카드 1개 표시, 자동 선택 상태로 시작. 파티 구성 없이 즉시 "출발" 가능.

- **장비 인벤토리 비어있음**: 장착 슬롯 "없음" 상태로 표시. 장착 없이 출발 가능.

- **3명 선택 후 추가 탭**: 선택 무시. 교체 원할 경우 기존 슬롯 탭으로 제거 후 재선택.

- **RunResult → MainMenu → 재런 시작**: 파티 구성 화면 초기화 — 이전 파티 선택 미유지 (MVP).

## Visual/Audio Requirements

이 시스템은 UI 흐름을 오케스트레이션한다. 화면 렌더링은 `#20 UI/HUD` 및 PartySelectScreen 씬 소유.

## UI Requirements

PartySelectScreen (S-03) 구성 (`#20 UI/HUD` 소유):
1. **동료 카드 그리드** — 해금 동료 최대 4장, 선택 시 파티 슬롯 이동
2. **파티 슬롯 3개** — 선택된 동료 초상화·이름 표시, 탭으로 제거 가능
3. **장비 패널** — 파티 슬롯 선택 시 해당 동료의 weapon/armor 슬롯 + 인벤토리 표시
4. **"출발" 버튼** — 파티 1명 이상 시 활성, 탭으로 런 시작
5. **동료 스탯 미리보기 (2026-07-26 리비전 — 델타 표시 추가)** — 장비 포함 effective_atk, effective_def를 절대값뿐 아니라 **장비 교체 시 변화량("+3 DEF" 등)**도 함께 표시. `#4 장비` 리뷰에서 확정된 무기 슬롯의 ATK/DEF 트레이드오프(power_ring 등)가 절대값만 봐서는 체감되지 않는다는 지적 반영 — 절대 수치만으로는 "이 장비가 뭘 바꿨는지"가 안 보임.

📌 **UX Flag**: 터치 최소 44×44px. 동료 카드·파티 슬롯·장비 패널 레이아웃은 `/ux-design`에서 확정.

## Acceptance Criteria

1. (해금 동료 표시, 2026-07-26 리비전 — 렌더링 주장 제거) GIVEN `unlocked_companions = ["warrior_base_01", "hidden_archer_03"]` WHEN 파티 구성 화면 진입 THEN 동료 카드 그리드에 바인딩되는 목록이 이 두 id와 정확히 일치한다. (실제 카드가 화면에 그려지는지는 `#20 UI/HUD`의 AC 범위.)

2. (파티 선택) GIVEN 동료 카드 탭 WHEN 파티 슬롯에 여유 있음 THEN 해당 동료가 파티 슬롯에 추가된다.

3. (최대 3명 제한) GIVEN 파티 슬롯 3개 모두 채워진 상태 WHEN 추가 동료 카드 탭 THEN 선택이 무시된다.

3b. (중복 선택 방지, 2026-07-26 추가) GIVEN 동료가 이미 파티 슬롯에 있는 상태에서 WHEN 같은 동료 카드를 다시 탭하면 THEN 선택이 무시되고 중복 추가되지 않는다.

4. (출발 버튼 비활성) GIVEN 파티 슬롯 모두 비어있을 때 THEN "출발" 버튼 비활성. (버튼 노드 자체의 `disabled` 속성이 아니라 이 시스템이 노출하는 활성화 상태/신호를 검증 대상으로 한다 — 실제 노드는 `#20` 소유.)

5. (출발 버튼 활성) GIVEN 파티 슬롯에 1명 이상 THEN "출발" 버튼 활성. (동일 — 상태/신호 기준.)

6. (장비 장착) GIVEN 인벤토리에 "iron_sword" 보유 WHEN weapon 슬롯에 장착 THEN `party_config[i].weapon_slot = "iron_sword"`로 설정된다.

6b. (미장착 슬롯, 2026-07-26 추가) GIVEN 어떤 동료도 장비를 장착하지 않은 상태에서 WHEN "출발"이 호출되면 THEN `party_config`의 모든 항목에서 `weapon_slot`과 `armor_slot`이 `""`이다 (null이 아님).

6c. (스탯 델타 표시, 2026-07-26 추가) GIVEN 동료의 armor_slot을 "" → "chain_mail"(DEF+5)로 교체할 때 WHEN 스탯 미리보기가 갱신되면 THEN effective_def의 절대값과 함께 변화량("+5")도 함께 노출된다.

7. (런 시작 호출, 2026-07-26 리비전 — 소유권 범위 축소) GIVEN "출발" 버튼 탭이고 파티 1명 이상인 상태에서 WHEN 처리되면 THEN `RunManager.start_run(party_config)`가 올바른 인자로 정확히 1회 호출되고 `SceneManager.go_to(S-04, FADE)`가 호출된다 (`RunManager`/`SceneManager`는 mock/spy로 대체 — 실제 런 초기화 성공 여부는 `#13`의 AC 범위, 씬 전환 완료는 `#19`의 AC 범위이며 이 시스템은 올바른 호출까지만 보증한다).

8. (기본 동료 자동 선택) GIVEN 해금 동료가 기본 동료 1명뿐 WHEN 파티 구성 화면 진입 THEN 기본 동료가 파티 슬롯 1번에 자동 배치되어 즉시 출발 가능.
