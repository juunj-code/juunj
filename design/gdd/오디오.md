## Overview

오디오 시스템은 게임 내 모든 BGM(배경음악)과 SFX(효과음) 재생을 소유하는 순수 출력(output-only) 레이어다. 다른 시스템이 이미 발신하고 있는 신호(씬 전환, 전투 HP 변화, 히든 발견, 런 종료)를 구독해 소리를 재생할 뿐, 어떤 게임플레이 로직에도 개입하지 않고 어떤 게임 상태도 소유하지 않는다 — 오디오가 꺼지거나 재생에 실패해도 게임 진행에는 전혀 지장이 없어야 한다(#8 시너지가 UI를 소유하지 않는 것과 같은 "관찰자, 개입자 아님" 원칙).

MVP 스코프는 `game-concept.md`가 이미 명시한 "Moderate" 오디오 니즈를 그대로 따른다: 던전 탐색 루프 BGM, 전투 루프 BGM(일반/보스 구분), 전투 효과음(피격·회복), 히든 발견 전용 특수 사운드, 런 결과(승리/패배) 스팅어. (2026-08-08 리비전 — UI 탭 사운드는 오너십 공백이 발견되어 스코프 제외, Open Questions 참조.)

## Player Fantasy

플레이어가 원하는 감정: **차분하고 신비로운 던전 탐색감**, 그리고 **히든 동료를 발견했을 때의 청각적 "찾았다!" 순간**. 던전 루프 BGM은 미니멀한 칩튠으로 위협보다는 탐험과 발견의 기대감을 깔아준다 — Pillar 1 "발견의 기쁨"을 시각(#3 동료 해금의 플래시 연출)뿐 아니라 청각으로도 확인시켜주는 것이 이 시스템의 핵심 존재 이유다. 전투 SFX는 화려함보다 명확성을 우선한다 — 미니멀한 8비트 사운드로 "내가 방금 뭘 했는지"가 즉시 들리게 하되, 오직 히든 발견 순간만은 다른 모든 소리와 뚜렷이 구별되는 특별한 사운드로 취급해 그 순간의 희소성을 청각적으로도 강조한다.

레퍼런스: 포켓몬로그·바람의나라류의 향수 어린 칩튠 감성(`game-concept.md` Inspiration 참조) — 다만 위협적인 톤보다는 "차분한 탐험" 쪽으로 기운다(사용자 결정, 짧은 세션·캐주얼 타겟 플레이어 프로필과 일관).

> lean 모드 — 이 섹션은 `creative-director` 상담 없이 작성. 필요 시 나중에 검토 요청 가능.

## Detailed Design

### Core Rules

1. **오너십 경계**: 이 시스템은 게임 상태를 읽거나 쓰지 않는다 — 오직 다른 시스템이 이미 발신하는 신호를 구독해 재생 함수를 호출할 뿐이다. 재생 실패(에셋 누락 등)는 `push_warning`으로 기록하고 무시 — 게임 진행을 막지 않는다(Graceful Degradation, `.claude/rules/engine-code.md`).
2. **버스 구성**: `Music`, `SFX` 두 개의 독립 오디오 버스(Godot `AudioServer` 버스)를 사용한다. 각 버스는 독립적으로 볼륨 조절 가능(현재는 고정 기본값, 실제 슬라이더 UI는 `#23 설정` 소관 — Open Questions 참조).
3. **BGM 트랙 카탈로그(MVP)**: `bgm_menu`(메인메뉴·파티선택 공용), `bgm_dungeon`(던전 탐색, 층 공통 1트랙 — 층별 개별 트랙은 Vertical Slice 이후 YAGNI), `bgm_battle_normal`(일반 전투), `bgm_battle_boss`(보스방 전투). 승리/패배는 짧은 스팅어(SFX 취급, 아래 6번) 재생 후 BGM 없이 결과 화면 유지.
4. **씬 전환 시 BGM 크로스페이드**: `#19 씬 관리`의 `scene_ready`/`scene_exited` 신호를 구독해, 진입하는 씬에 대응하는 BGM 트랙으로 크로스페이드한다(Formulas 참조). **이미 재생 중인 트랙과 동일한 트랙으로 전환하는 경우 재시작하지 않는다**(끊김 방지 — Edge Cases 참조).
5. **전투 SFX는 `#1 턴제 전투`의 `unit_hp_changed(unit_id, unit_index, new_hp)` 신호(2026-08-08 리비전 — `unit_index` 3번째 인자로 정정: `#1`이 같은 날 TD-001을 고치며 이 신호에 인스턴스 인덱스를 추가했는데 이 GDD가 갱신을 놓쳤음, 독립 검토에서 발견)의 HP 변화 부호로 판별한다**: `(unit_id, unit_index)` **조합을 키로** 이전 관측값을 추적해, 감소했으면 `sfx_hit`, 증가했으면 `sfx_heal`, 변화 없으면 재생하지 않는다. `unit_id`만으로 키를 잡으면 같은 `enemy_id`를 공유하는 두 적 인스턴스의 HP가 서로의 SFX 판정을 오염시킨다(TD-001과 동일한 근본 원인) — 반드시 두 값을 함께 키로 쓴다. 다른 시스템의 상태를 직접 읽지 않고 신호로 받은 값만으로 판별하는 원칙(폴링 금지 컨벤션, ADR-0012)은 유지된다.
6. **히든 발견 전용 사운드**: `#9 히든 트리거`의 `companion_discovered(id)` 신호를 구독해 `sfx_hidden_discovery`를 재생한다. 이 사운드는 SFX 버스에 속하지만 다른 모든 전투 SFX와 명확히 구별되는 별도 자산이다(사용자 결정 — Player Fantasy 참조. 구체적 음색 스펙은 Visual/Audio Requirements 참조 — 2026-08-08 리비전: 원안의 "특별한 사운드"라는 서술만으로는 실제 생성 시 근거가 부족하다는 audio-director 지적 반영).
7. **런 결과 스팅어**: `#13 런 상태 관리`의 `run_ended(success: bool)` 신호를 구독해 `sfx_victory` 또는 `sfx_defeat`를 1회 재생한다.
8. **보스 BGM 판별은 `#11 EnemyRegistry` 조회로 이루어진다(2026-08-08 리비전 — 원안은 `combat_entered`가 전달하는 적 목록에 `is_boss` 필드가 직접 있다고 가정했으나, 실제 `EnemyRunState`엔 `enemy_id`만 있고 `is_boss`는 `EnemyData`(레지스트리) 소관 — godot-specialist 지적으로 발견)**: `#13`의 `combat_entered(enemies: Array[EnemyRunState])`를 수신하면, 각 유닛의 `enemy_id`로 `EnemyRegistry.get_by_id(enemy_id).is_boss`를 조회한다(`#4 장비`가 이미 `CompanionRegistry.get_by_id()`로 하는 것과 동일한 패턴). 이건 Core Rule 5가 금지하는 "폴링"이 아니다 — 매 프레임 반복 조회가 아니라 신호 수신 시점 1회, 그것도 다른 시스템의 *변하는 런타임 상태*가 아니라 정적 레지스트리 데이터(게임 시작 시 로드되고 이후 불변)를 읽는 것이기 때문이다. 하나라도 `is_boss=true`면 `bgm_battle_boss`, 아니면 `bgm_battle_normal`.
9. **디버그 관측용 조회 함수(2026-08-08 리비전 추가 — qa-lead 지적: 재생 여부를 테스트가 검증할 방법이 없었음)**: `get_current_bgm_id() -> String`과 `get_last_played_sfx_id() -> String`을 노출한다. 플레이어에게 보이지 않는 순수 조회용 상태지만(UI 없음 원칙은 그대로 유지), 이 값이 있어야 Acceptance Criteria가 실제로 자동 테스트 가능해진다 — Player Fantasy의 "노골적으로 안 보여준다" 철학은 플레이어 대상 UI 얘기지 개발자/테스트 관측성 얘기가 아니다.

> **UI 탭 사운드(`play_ui_tap()`/`sfx_ui_tap`)는 이 리비전에서 스코프 제외(2026-08-08, creative-director 권고 채택)**: 원안은 "`#20`이 호출 시점을 소유한다"고 서술했지만, `UI-HUD.md`(Approved) 어디에도 실제로 `play_ui_tap()`을 호출하겠다는 약속이 없었다 — 두 문서 중 어느 쪽도 오너를 자처하지 않는 고아 기능이었다(독립 검토에서 발견). 지금 양쪽을 동시에 패치하기보다, 실제로 필요해지는 시점(`#20`이 이 기능을 요구하거나 `#23`이 설계될 때)에 `#20`/`#23` GDD 쪽에서 명시적으로 다시 끌어오는 걸로 미룬다 — Open Questions 참조.

## Formulas

### BGM 크로스페이드 볼륨 (2026-08-08 리비전 — 등파워 크로스페이드로 교체)

**원안의 문제(audio-director 지적)**: 선형 dB lerp는 중간 지점에서 두 트랙이 똑같이 -23dB(예시)로 내려가 있는 상태라, 두 트랙의 실제 음압을 합쳐도 정상 재생(-6dB) 대비 체감상 훅 꺼지는 "구멍"이 들린다. 매 씬 전환·전투 진입마다 반복되는 가장 빈번한 오디오 이벤트에서 이 결점이 그대로 드러난다. **또한 원안은 "버스 볼륨"을 크로스페이드 대상으로 서술했는데, Godot의 버스 볼륨(`AudioServer.set_bus_volume_db`)은 버스 하나에 값 하나뿐이라 같은 `Music` 버스에 걸린 두 트랙에 서로 다른 음량을 동시에 줄 수 없다** — 실제로는 트랙마다 별도 `AudioStreamPlayer` 노드(둘 다 `Music` 버스로 라우팅)를 두고, 크로스페이드는 버스가 아니라 **각 플레이어 자신의 `volume_db`**를 조절해야 한다(godot-specialist 확인).

등파워(equal-power) 크로스페이드는 선형 진폭이 아니라 `sin`/`cos`로 이득(gain)을 계산해, 두 트랙의 (진폭)² 합이 항상 1로 일정하게 유지되도록 한다 — 이게 사람 귀에 "일정한 음량"으로 들리는 실제 조건이다:

`fade_out_gain(t) = cos(clamp(t / CROSSFADE_DURATION, 0.0, 1.0) * PI / 2)` — 나가는 트랙, 1→0
`fade_in_gain(t) = sin(clamp(t / CROSSFADE_DURATION, 0.0, 1.0) * PI / 2)` — 들어오는 트랙, 0→1
`player.volume_db = linear_to_db(gain)` — Godot 내장 `linear_to_db()`로 선형 이득을 dB로 변환해 각 `AudioStreamPlayer.volume_db`에 대입

**변수:**

| 변수 | 타입 | 범위 | 설명 |
|------|------|------|------|
| `t` | float | 0.0 ~ `CROSSFADE_DURATION` | 크로스페이드 시작 후 경과 시간(초) |
| `fade_out_gain` / `fade_in_gain` | float | 0.0 ~ 1.0 | 선형 진폭 이득(dB 아님) — `linear_to_db()`를 거쳐야 플레이어 볼륨이 됨 |
| `CROSSFADE_DURATION` | const float | 0.5 | 크로스페이드 지속 시간(초), Tuning Knobs 참조 |

**Output Range**: `fade_out_gain`은 1.0(전체 음량)에서 0.0(무음)으로, `fade_in_gain`은 0.0에서 1.0으로 — 임의의 `t`에서 `fade_out_gain(t)² + fade_in_gain(t)² = 1`(등파워 항등식). `t >= CROSSFADE_DURATION`이면 각각 0.0/1.0에 고정.

**Example**: `CROSSFADE_DURATION=0.5`, 중간 지점 `t=0.25`일 때: `fade_out_gain = cos(π/4) ≈ 0.707`, `fade_in_gain = sin(π/4) ≈ 0.707` — `0.707² + 0.707² = 1.0`, 즉 두 트랙의 합산 음압이 시작·끝과 동일하게 유지된다(원안의 선형 버전은 이 지점에서 `0.5² + 0.5² = 0.5`로 절반까지 떨어져 "구멍"이 들렸음). `linear_to_db(0.707) ≈ -3dB`로 두 플레이어의 `volume_db`를 설정한다.

## Edge Cases

- **씬 전환 시 목표 BGM이 이미 재생 중인 트랙과 동일한 경우**: 재생 위치(`playback_position`)를 유지한 채 크로스페이드를 시작하지 않는다 — 검증 가능한 기준은 "재시작 전후 `playback_position`이 0으로 리셋되지 않았는가"(2026-08-08 리비전 — 원안의 "끊김 방지"는 서술뿐이라 qa-lead 지적으로 관측 가능한 조건으로 구체화). 예: 파티 선택 화면에서 메인 메뉴로 돌아가도 둘 다 `bgm_menu`라 아무 일도 일어나지 않는다.
- **`unit_hp_changed`가 변화 없이(동일 값으로) 발신되는 경우**: SFX를 재생하지 않는다. 결정론적 전투(크리티컬/회피 없음)에서는 발생 빈도가 낮지만, 방어 스킬 등으로 데미지가 0이 되는 미래 확장 시 자연스럽게 처리된다.
- **여러 SFX가 동시에 트리거되는 경우** (예: 전체 회복 스킬로 파티원 3명의 `unit_hp_changed`가 한 틱에 연달아 발신): 서로 다른 유닛의 SFX는 폴리포니(중첩 재생) 그대로 허용한다. **단, 같은 `sfx_id`가 같은 프레임에 재요청되면 재생하지 않고 무시한다**(2026-08-08 리비전 — 원안은 무제한 중첩을 허용해 `all_allies` 회복처럼 여러 유닛이 한 틱에 같은 `sfx_heal`을 동시에 트리거하면 위상이 어긋난 채 겹쳐 뭉개진 소리가 나는 문제를 audio-director가 지적, creative-director는 별도 우선순위 큐가 아니라 프레임 단위 동일-id 중복 억제 한 줄로 충분하다고 판단). 서로 다른 `sfx_id`끼리는 여전히 자유롭게 겹친다 — Godot의 `AudioStreamPlayer` 풀이 그대로 지원.
- **에셋 로드 실패(존재하지 않는 sfx/bgm id 요청)**: `push_warning` 출력 후 무시 — 게임 진행에 영향 없음(Core Rule 1).
- **브라우저 탭 백그라운드 전환**: `#1`/`#19`가 이미 문서화한 메커니즘과 동일(requestAnimationFrame 정지로 Godot 프레임 콜백 자체가 멈춤) — 오디오도 자연히 멈췄다가 탭 복귀 시 이어진다. 별도 처리 불필요.
- **볼륨 0(음소거) 설정 시**: 버스 볼륨만 낮아질 뿐 재생 로직 자체는 우회하지 않는다(`#23 설정` 완성 전까지는 애초에 이 상황이 발생하지 않음).

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 너무 낮을 때 | 너무 높을 때 |
|--------|-----------|-----------|-------------|-------------|
| `CROSSFADE_DURATION` | 0.5초 | 0.3~1.5초 | 트랙 전환이 뚝 끊기는 느낌 | 씬 전환 직후에도 이전 BGM이 한동안 섞여 들려 어색함 |
| `Music` 버스 기본 볼륨 | -6dB | -12~0dB | 던전 분위기가 안 느껴짐 | SFX와 경쟁해 피격/회복 SFX 명료도 저하 |
| `SFX` 버스 기본 볼륨 | 0dB | -6~+3dB | 액션 피드백이 약해 Pillar 4의 "명확한 전투"를 해침 | 반복 재생되는 전투 SFX가 피로감 유발 |

> **볼륨 위계 불변식(2026-08-08 리비전 추가 — audio-director 지적)**: `Music`과 `SFX` 두 버스의 안전 범위가 겹쳐서, `#23 설정`이 완성돼 사용자가 두 볼륨을 자유롭게 조절하게 되면 이론상 `Music`이 `SFX`보다 커져 위계가 뒤집힐 수 있다. **규칙**: `SFX` 버스 볼륨은 항상 `Music` 버스 볼륨보다 최소 3dB 이상 높게 유지한다(사용자가 두 슬라이더를 직접 조절해도 `#23`이 이 하한을 강제) — 전투 SFX 명료도가 시스템 불변식으로 보장되어야 하는 이유는 위 "너무 낮을 때" 칸 참조.

## Visual/Audio Requirements

이 GDD 자체가 오디오 시스템이므로, 이 섹션은 실제 필요한 오디오 에셋 카탈로그를 명시한다(이후 `/asset-spec`으로 세부 생성 프롬프트화):

**포맷 스펙(2026-08-08 리비전 추가 — audio-director 지적, 원안엔 없었음)**: 전부 44.1kHz, 16-bit PCM(`.ogg` 압축 권장, 웹 export 용량 고려). BGM 러프 타깃 -16 LUFS integrated, SFX 원샷은 -12 LUFS(SFX가 BGM보다 크게 들려야 하는 위계는 Tuning Knobs의 볼륨 위계 불변식과 일관). 정확한 LUFS 튜닝은 실제 생성/마스터링 세션에서 확정.

| 에셋 ID | 종류 | 길이/루프 | 톤 노트 |
|---------|------|-----------|---------|
| `bgm_menu` | BGM, 루프 | 30~60초 루프 | 차분한 칩튠, 메인메뉴·파티선택 공용 |
| `bgm_dungeon` | BGM, 루프 | 30~60초 루프 | 미니멀 멜로디, 신비롭고 차분한 톤 — 위협감 최소화(사용자 결정) |
| `bgm_battle_normal` | BGM, 루프 | 20~40초 루프 | 던전 루프보다 템포 업, 그러나 여전히 8비트 미니멀 |
| `bgm_battle_boss` | BGM, 루프 | 20~40초 루프 | `bgm_battle_normal`보다 긴장감 있는 변주(같은 모티프 재편곡 권장 — 별도 세션에서 결정) |
| `sfx_hit` | SFX, 원샷 | <0.5초 | 미니멀 8비트 타격음, **사각파(square wave) 기반** |
| `sfx_heal` | SFX, 원샷 | <0.5초 | 미니멀 8비트, **사각파 기반**, `sfx_hit`과 명확히 구별되는 상승조 |
| `sfx_hidden_discovery` | SFX, 원샷 | 1~2초 | **파형부터 다른 계열로 격리(2026-08-08 리비전 — audio-director 지적, 원안의 "특별한 사운드"는 생성 근거로 부족했음)**: 위 전투 SFX(사각파)와 달리 **삼각파/사인파 기반 벨·차임 음색**, 상승하는 3음 아르페지오(예: 장3화음, 음당 ~80ms) — 파형 자체가 다르므로 다른 모든 SFX와 절대 혼동되지 않는다(사용자 결정 — Player Fantasy 핵심) |
| `sfx_victory` | SFX, 원샷 | 1~3초 | 짧고 밝은 스팅어 |
| `sfx_defeat` | SFX, 원샷 | 1~3초 | 짧고 차분한(과도하게 우울하지 않은) 스팅어 — Pillar 2 "성장은 영원하다"와 톤이 부딪히지 않도록 |

**제작 범위 결정(2026-08-08, 사용자 결정)**: 이번 세션은 GDD(스펙)까지만 — 실제 에셋 생성(BGM/SFX 파일)은 별도 세션에서 진행. 톤 방향(BGM: 차분하고 신비로운 칩튠 / SFX: 미니멀 8비트 전반 + 히든 발견만 특별)은 이미 확정. `sfx_ui_tap`은 이 리비전에서 카탈로그 제외(Core Rule 9 하단 노트 참조 — UI 탭 사운드 스코프 제외와 함께 제거).

## Acceptance Criteria

**2026-08-08 리비전 — 전면 재작성(qa-lead 지적)**: 원안의 모든 AC는 "재생된다"만 서술하고 이를 실제로 어떻게 관측/검증하는지가 없었다. 아래는 Core Rule 9의 `get_current_bgm_id()`/`get_last_played_sfx_id()` 조회 함수를 관측 지점으로 명시한다.

1. GIVEN `#19`의 `scene_ready("S-03")`(던전 탐색 씬 ID, `씬-관리.md` 참조)가 발신되면, WHEN 그 직후 `get_current_bgm_id()`를 조회하면, THEN `"bgm_dungeon"`이 반환된다(또는 크로스페이드 완료를 기다린 후 조회).
2. GIVEN 이미 `bgm_dungeon`이 재생 중이고 `playback_position > 0`인 상태에서, WHEN 같은 씬으로의 `scene_ready`가 다시 발신되면(예: 화면 재진입), THEN 크로스페이드가 다시 시작되지 않고 해당 트랙 `AudioStreamPlayer`의 `playback_position`이 리셋되지 않는다(0으로 되돌아가지 않음).
3. GIVEN `#13`의 `combat_entered(enemies)`가 `EnemyRegistry.get_by_id(enemy_id).is_boss=true`인 적을 포함해 발신되면, WHEN `get_current_bgm_id()`를 조회하면, THEN `"bgm_battle_boss"`가 반환된다(일반 전투 시 `"bgm_battle_normal"`).
4. GIVEN 유닛 `(unit_id, unit_index)`의 `unit_hp_changed`가 그 조합의 이전 관측값보다 낮은 새 HP로 발신되면, WHEN 그 직후 `get_last_played_sfx_id()`를 조회하면, THEN `"sfx_hit"`가 반환된다.
5. GIVEN 유닛 `(unit_id, unit_index)`의 `unit_hp_changed`가 그 조합의 이전 관측값보다 높은 새 HP로 발신되면, WHEN 그 직후 `get_last_played_sfx_id()`를 조회하면, THEN `"sfx_heal"`이 반환된다.
6. GIVEN 서로 다른 두 유닛이 같은 `unit_id`를 공유하지만 `unit_index`가 다를 때(TD-001 시나리오, 예: 같은 `enemy_id`의 적 2마리), WHEN 한 유닛만 HP가 감소하는 `unit_hp_changed`를 발신하면, THEN `sfx_hit`가 재생되고, 나머지 유닛의 마지막 관측 HP는 영향받지 않는다(그 유닛의 HP가 실제로 바뀌기 전까지는 어떤 SFX도 트리거되지 않음).
7. GIVEN 유닛의 `unit_hp_changed`가 이전과 동일한 값으로 발신되면, WHEN 그 직후 `get_last_played_sfx_id()`를 조회하면, THEN 이 이벤트로 인한 갱신이 없다(직전 값 그대로 — 아무 SFX도 새로 재생되지 않음).
8. GIVEN `#9`의 `companion_discovered(id)`가 발신되면, WHEN 그 직후 `get_last_played_sfx_id()`를 조회하면, THEN `"sfx_hidden_discovery"`가 반환된다 — 이는 `"sfx_hit"`/`"sfx_heal"`과 다른 **`sfx_id` 문자열**이다(2026-08-08 리비전 — 원안의 "다른 오디오 스트림"이 노드 인스턴스를 뜻하는지 자산을 뜻하는지 모호했다는 qa-lead 지적 반영, `sfx_id` 비교로 명확화).
9. GIVEN `#13`의 `run_ended(success=true)`가 발신되면, WHEN 그 직후 `get_last_played_sfx_id()`를 조회하면, THEN `"sfx_victory"`가 반환된다(`success=false`이면 `"sfx_defeat"`).
10. GIVEN 존재하지 않는 sfx/bgm id로 재생이 요청되면, WHEN 재생 함수가 호출되면, THEN `push_warning`이 출력되고 예외 없이 정상 반환되며 `get_current_bgm_id()`/`get_last_played_sfx_id()`는 이전 값 그대로 유지된다(게임 진행 차단 없음).
11. GIVEN 크로스페이드가 `CROSSFADE_DURATION`(0.5초) 진행 중일 때, WHEN 정확히 중간 시점(`t=0.25`)의 `fade_out_gain`/`fade_in_gain`을 계산하면, THEN 둘 다 `≈0.707`이고 `fade_out_gain² + fade_in_gain² ≈ 1.0`(등파워 항등식, 순수 함수 단위 테스트로 검증 — 실제 재생 없이 `Synergy`/`HudRules` 같은 순수 로직 클래스와 동일한 방식).
