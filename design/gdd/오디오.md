# 오디오 (Audio)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-08-08

> **Creative Director Review (CD-GDD-ALIGN)**: Skipped — Lean 모드 (저작 세션). 독립 `/design-review`는 별도 세션에서 필요.

## Overview

오디오 시스템은 게임 내 모든 BGM(배경음악)과 SFX(효과음) 재생을 소유하는 순수 출력(output-only) 레이어다. 다른 시스템이 이미 발신하고 있는 신호(씬 전환, 전투 HP 변화, 히든 발견, 런 종료)를 구독해 소리를 재생할 뿐, 어떤 게임플레이 로직에도 개입하지 않고 어떤 게임 상태도 소유하지 않는다 — 오디오가 꺼지거나 재생에 실패해도 게임 진행에는 전혀 지장이 없어야 한다(#8 시너지가 UI를 소유하지 않는 것과 같은 "관찰자, 개입자 아님" 원칙).

MVP 스코프는 `game-concept.md`가 이미 명시한 "Moderate" 오디오 니즈를 그대로 따른다: 던전 탐색 루프 BGM, 전투 루프 BGM(일반/보스 구분), 전투 효과음(피격·회복), 히든 발견 전용 특수 사운드, 런 결과(승리/패배) 스팅어, UI 탭 사운드.

## Player Fantasy

플레이어가 원하는 감정: **차분하고 신비로운 던전 탐색감**, 그리고 **히든 동료를 발견했을 때의 청각적 "찾았다!" 순간**. 던전 루프 BGM은 미니멀한 칩튠으로 위협보다는 탐험과 발견의 기대감을 깔아준다 — Pillar 1 "발견의 기쁨"을 시각(#3 동료 해금의 플래시 연출)뿐 아니라 청각으로도 확인시켜주는 것이 이 시스템의 핵심 존재 이유다. 전투 SFX는 화려함보다 명확성을 우선한다 — 미니멀한 8비트 사운드로 "내가 방금 뭘 했는지"가 즉시 들리게 하되, 오직 히든 발견 순간만은 다른 모든 소리와 뚜렷이 구별되는 특별한 사운드로 취급해 그 순간의 희소성을 청각적으로도 강조한다.

레퍼런스: 포켓몬로그·바람의나라류의 향수 어린 칩튠 감성(`game-concept.md` Inspiration 참조) — 다만 위협적인 톤보다는 "차분한 탐험" 쪽으로 기운다(사용자 결정, 짧은 세션·캐주얼 타겟 플레이어 프로필과 일관).

> lean 모드 — 이 섹션은 `creative-director` 상담 없이 작성. 필요 시 나중에 검토 요청 가능.

## Detailed Design

### Core Rules

1. **오너십 경계**: 이 시스템은 게임 상태를 읽거나 쓰지 않는다 — 오직 다른 시스템이 이미 발신하는 신호를 구독해 재생 함수를 호출할 뿐이다. 재생 실패(에셋 누락 등)는 `push_warning`으로 기록하고 무시 — 게임 진행을 막지 않는다(Graceful Degradation, `.claude/rules/engine-code.md`).
2. **버스 구성**: `Music`, `SFX` 두 개의 독립 오디오 버스(Godot `AudioServer` 버스)를 사용한다. 각 버스는 독립적으로 볼륨 조절 가능(현재는 고정 기본값, 실제 슬라이더 UI는 `#23 설정` 소관 — Open Questions 참조).
3. **BGM 트랙 카탈로그(MVP)**: `bgm_menu`(메인메뉴·파티선택 공용), `bgm_dungeon`(던전 탐색, 층 공통 1트랙 — 층별 개별 트랙은 Vertical Slice 이후 YAGNI), `bgm_battle_normal`(일반 전투), `bgm_battle_boss`(보스방 전투, `#11 EnemyData.is_boss` 기준으로 분기). 승리/패배는 짧은 스팅어(SFX 취급, 아래 6번) 재생 후 BGM 없이 결과 화면 유지.
4. **씬 전환 시 BGM 크로스페이드**: `#19 씬 관리`의 `scene_ready`/`scene_exited` 신호를 구독해, 진입하는 씬에 대응하는 BGM 트랙으로 크로스페이드한다(Formulas 참조). **이미 재생 중인 트랙과 동일한 트랙으로 전환하는 경우 재시작하지 않는다**(끊김 방지 — Edge Cases 참조).
5. **전투 SFX는 `#1 턴제 전투`의 `unit_hp_changed(unit_id, new_hp)` 신호의 HP 변화 부호로 판별한다**: 이전 관측값보다 감소했으면 `sfx_hit`, 증가했으면 `sfx_heal`, 변화 없으면 재생하지 않는다. 이 시스템이 유닛별 마지막 HP를 자체적으로 추적한다(다른 시스템의 상태를 직접 읽지 않고, 신호로 받은 값만으로 판별 — 폴링 금지 컨벤션, ADR-0012와 일관).
6. **히든 발견 전용 사운드**: `#9 히든 트리거`의 `companion_discovered(id)` 신호를 구독해 `sfx_hidden_discovery`를 재생한다. 이 사운드는 SFX 버스에 속하지만 다른 모든 전투 SFX와 명확히 구별되는 별도 자산이다(사용자 결정 — Player Fantasy 참조).
7. **런 결과 스팅어**: `#13 런 상태 관리`의 `run_ended(success: bool)` 신호를 구독해 `sfx_victory` 또는 `sfx_defeat`를 1회 재생한다.
8. **UI 탭 사운드는 이 시스템이 오너십을 갖지 않는다**: `#21`은 `play_ui_tap()` 같은 재생 함수만 제공하고, **언제 호출할지는 각 화면(`#20 UI/HUD`가 소유한 실제 Button 노드)이 결정한다** — `#4 장비`의 `equip()`을 `#1`이 호출 시점을 결정하는 것과 동일한 오너십 패턴. `#21`이 UI 이벤트를 직접 구독하지 않는 이유: 어떤 탭이 "의미 있는 탭"인지(예: 비활성 버튼 탭은 소리 없음)는 UI 로직의 영역이지 오디오의 영역이 아니기 때문.

### States and Transitions

| 상태 | 트리거 | 설명 |
|------|--------|------|
| 무음 | 부팅 직후 | 재생 중인 BGM 없음 |
| 재생 중 | `scene_ready` 또는 전투 시작 | 해당 씬/상황의 BGM 트랙 재생 중 |

## Formulas

### BGM 크로스페이드 볼륨

크로스페이드 중 각 트랙(fading-out / fading-in)의 버스 볼륨은 다음과 같이 선형 보간된다:

`crossfade_volume_db(t) = lerp(from_db, to_db, clamp(t / CROSSFADE_DURATION, 0.0, 1.0))`

**변수:**

| 변수 | 타입 | 범위 | 설명 |
|------|------|------|------|
| `t` | float | 0.0 ~ `CROSSFADE_DURATION` | 크로스페이드 시작 후 경과 시간(초) |
| `from_db` / `to_db` | float | -40 ~ 0 | 시작/목표 데시벨 값(음소거 근사치 -40dB, 기본 재생 음량 0dB — Godot `AudioServer` 버스 볼륨은 dB 단위) |
| `CROSSFADE_DURATION` | const float | 0.5 | 크로스페이드 지속 시간(초), Tuning Knobs 참조 |

**Output Range**: `from_db`에서 `to_db`까지 선형 이동. `t >= CROSSFADE_DURATION`이면 `to_db`에 고정(오버슈트 없음).

**Example**: 이전 트랙 -6dB(정상 음량)에서 페이드아웃(-6→-40dB), 새 트랙 -40dB(무음)에서 페이드인(-40→-6dB), `CROSSFADE_DURATION=0.5`. `t=0.25`(중간 지점)일 때: 이전 트랙 `lerp(-6,-40,0.5)=-23dB`, 새 트랙 `lerp(-40,-6,0.5)=-23dB` — 두 트랙이 같은 음량에서 교차한다.

## Edge Cases

- **씬 전환 시 목표 BGM이 이미 재생 중인 트랙과 동일한 경우**: 크로스페이드를 시작하지 않는다(재시작으로 인한 끊김 방지) — 예: 파티 선택 화면에서 메인 메뉴로 돌아가도 둘 다 `bgm_menu`라 아무 일도 일어나지 않는다.
- **`unit_hp_changed`가 변화 없이(동일 값으로) 발신되는 경우**: SFX를 재생하지 않는다. 결정론적 전투(크리티컬/회피 없음)에서는 발생 빈도가 낮지만, 방어 스킬 등으로 데미지가 0이 되는 미래 확장 시 자연스럽게 처리된다.
- **여러 SFX가 동시에 트리거되는 경우** (예: 전체 회복 스킬로 파티원 3명의 `unit_hp_changed`가 한 틱에 연달아 발신): 폴리포니(중첩 재생) 허용 — 별도 큐, 우선순위, 병합 로직 없음. Godot의 `AudioStreamPlayer` 풀로 동시 재생을 그대로 지원한다.
- **에셋 로드 실패(존재하지 않는 sfx/bgm id 요청)**: `push_warning` 출력 후 무시 — 게임 진행에 영향 없음(Core Rule 1).
- **브라우저 탭 백그라운드 전환**: `#1`/`#19`가 이미 문서화한 메커니즘과 동일(requestAnimationFrame 정지로 Godot 프레임 콜백 자체가 멈춤) — 오디오도 자연히 멈췄다가 탭 복귀 시 이어진다. 별도 처리 불필요.
- **볼륨 0(음소거) 설정 시**: 버스 볼륨만 낮아질 뿐 재생 로직 자체는 우회하지 않는다(`#23 설정` 완성 전까지는 애초에 이 상황이 발생하지 않음).

## Dependencies

### Upstream Dependencies (이 시스템이 의존하는 것)

| 시스템 | 의존 유형 | 사용하는 데이터 |
|--------|-----------|-----------------|
| `#19 씬 관리` | **Soft** — 신호가 없어도 재생은 가능하나(수동 트리거로 대체 가능) BGM 크로스페이드 타이밍을 잃음 | `scene_ready`, `scene_exited` 신호 (2026-08-08 기준 미구현 — 위 참조) |
| `#1 턴제 전투` | **Soft** — 전투 SFX 없이도 전투는 정상 진행됨 | `unit_hp_changed` 신호 |
| `#9 히든 트리거` | **Soft** | `companion_discovered` 신호 |
| `#13 런 상태 관리` | **Soft** | `run_ended`, `combat_entered` 신호 |
| `#11 적 데이터` | **Soft** — `combat_entered`로 전달되는 적 목록의 `is_boss` 필드만 읽음, 다른 데이터 불필요 | `is_boss` |

### Downstream Dependents (이 시스템에 의존하는 것)

이 시스템에 **Hard 의존하는 시스템은 없다** — 오디오가 완전히 꺼지거나 미구현이어도 어떤 게임로직도 깨지지 않는 것이 설계 원칙(Core Rule 1). `#20 UI/HUD`만 선택적으로 `play_ui_tap()`을 호출한다(Soft, 호출 안 해도 UI는 정상 동작).

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 너무 낮을 때 | 너무 높을 때 |
|--------|-----------|-----------|-------------|-------------|
| `CROSSFADE_DURATION` | 0.5초 | 0.3~1.5초 | 트랙 전환이 뚝 끊기는 느낌 | 씬 전환 직후에도 이전 BGM이 한동안 섞여 들려 어색함 |
| `Music` 버스 기본 볼륨 | -6dB | -12~0dB | 던전 분위기가 안 느껴짐 | SFX와 경쟁해 피격/회복 SFX 명료도 저하 |
| `SFX` 버스 기본 볼륨 | 0dB | -6~+3dB | 액션 피드백이 약해 Pillar 4의 "명확한 전투"를 해침 | 반복 재생되는 전투 SFX가 피로감 유발 |

## Visual/Audio Requirements

이 GDD 자체가 오디오 시스템이므로, 이 섹션은 실제 필요한 오디오 에셋 카탈로그를 명시한다(이후 `/asset-spec`으로 세부 생성 프롬프트화):

| 에셋 ID | 종류 | 길이/루프 | 톤 노트 |
|---------|------|-----------|---------|
| `bgm_menu` | BGM, 루프 | 30~60초 루프 | 차분한 칩튠, 메인메뉴·파티선택 공용 |
| `bgm_dungeon` | BGM, 루프 | 30~60초 루프 | 미니멀 멜로디, 신비롭고 차분한 톤 — 위협감 최소화(사용자 결정) |
| `bgm_battle_normal` | BGM, 루프 | 20~40초 루프 | 던전 루프보다 템포 업, 그러나 여전히 8비트 미니멀 |
| `bgm_battle_boss` | BGM, 루프 | 20~40초 루프 | `bgm_battle_normal`보다 긴장감 있는 변주(같은 모티프 재편곡 권장 — 별도 세션에서 결정) |
| `sfx_hit` | SFX, 원샷 | <0.5초 | 미니멀 8비트 타격음 |
| `sfx_heal` | SFX, 원샷 | <0.5초 | 미니멀 8비트, `sfx_hit`과 명확히 구별되는 상승조 |
| `sfx_hidden_discovery` | SFX, 원샷 | 1~2초 | 다른 모든 SFX와 뚜렷이 구별되는 특별한 반짝임/챠임 사운드(사용자 결정 — Player Fantasy 핵심) |
| `sfx_victory` | SFX, 원샷 | 1~3초 | 짧고 밝은 스팅어 |
| `sfx_defeat` | SFX, 원샷 | 1~3초 | 짧고 차분한(과도하게 우울하지 않은) 스팅어 — Pillar 2 "성장은 영원하다"와 톤이 부딪히지 않도록 |
| `sfx_ui_tap` | SFX, 원샷 | <0.2초 | 미니멀 클릭음, 모든 화면 공용 |

## Acceptance Criteria

1. GIVEN `#19`의 `scene_ready("S-03")`(던전 탐색 씬 ID, `씬-관리.md` 참조)가 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `bgm_dungeon` 트랙으로 크로스페이드가 시작된다.
2. GIVEN 이미 `bgm_dungeon`이 재생 중인 상태에서, WHEN 같은 씬으로의 `scene_ready`가 다시 발신되면(예: 화면 재진입), THEN 크로스페이드가 다시 시작되지 않고 기존 재생이 끊김 없이 유지된다.
3. GIVEN `#13`의 `combat_entered(enemies)`가 `is_boss=true`인 적을 포함해 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `bgm_battle_boss`로 전환된다(일반 전투 시 `bgm_battle_normal`과 구별).
4. GIVEN 유닛의 `unit_hp_changed`가 이전 관측값보다 낮은 새 HP로 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `sfx_hit`가 재생된다.
5. GIVEN 유닛의 `unit_hp_changed`가 이전 관측값보다 높은 새 HP로 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `sfx_heal`이 재생된다.
6. GIVEN 유닛의 `unit_hp_changed`가 이전과 동일한 값으로 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN 아무 SFX도 재생되지 않는다.
7. GIVEN `#9`의 `companion_discovered(id)`가 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `sfx_hidden_discovery`가 재생되고 이는 `sfx_hit`/`sfx_heal`과 다른 오디오 스트림이다.
8. GIVEN `#13`의 `run_ended(success=true)`가 발신되면, WHEN 오디오 시스템이 이를 수신하면, THEN `sfx_victory`가 1회 재생된다(`success=false`이면 `sfx_defeat`).
9. GIVEN 존재하지 않는 sfx/bgm id로 재생이 요청되면, WHEN 재생 함수가 호출되면, THEN `push_warning`이 출력되고 예외 없이 정상 반환된다(게임 진행 차단 없음).
10. GIVEN 크로스페이드가 `CROSSFADE_DURATION`(0.5초) 진행 중일 때, WHEN 정확히 중간 시점(`t=0.25`)의 볼륨을 조회하면, THEN 두 트랙 모두 시작값과 목표값의 정확히 중간 dB(예: -6dB↔-40dB 전환 시 -23dB)이다.
