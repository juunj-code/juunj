> **Status**: In Design

## Overview

런 결과 시스템은 런 종료 시 결과 화면을 표시하는 Progression 레이어 시스템이다. #13 RunManager로부터 런 종료 신호와 결과 데이터(승패, 도달 층수, `#14`가 검증까지 마친 이번 런 신규 해금 동료)를 받아 화면을 구성하고, #14 영구 진행에서 갱신된 해금 상태·최고 기록을 추가로 표시한다. 플레이어가 확인하면 메인메뉴로 돌아간다. 이 시스템은 화면 오케스트레이션만 담당하며, 영구 데이터 처리는 #14가 이 화면 표시 전에 완료한 상태다. (2026-07-26 리비전 — 아래 참조: `discovered_companions` 대신 `#14`가 검증한 `newly_unlocked`를 사용하도록 데이터 소스 정정.)

## Player Fantasy

"이 런 실패했지만 ○○는 해금됐다." — 실패해도 뭔가 남는다는 감각. 성공 시 "최고 기록 갱신!" 피드백.

## Detailed Rules

### 결과 화면 데이터

#13 RunManager `end_run()` 완료 후 이 시스템에 전달:

```gdscript
# 결과 화면 구성에 필요한 데이터
{
  "is_success": bool,
  "floor_reached": int,                        # 1~3
  "newly_unlocked": Array[String],              # #14.commit_run_end()가 발신하는 progress_committed(newly_unlocked, save_success) 신호값 (2026-07-26 리비전 — 아래 참조)
  "is_new_record": bool                         # #14가 최고 층수 갱신 여부 계산 후 전달
}
```

**2026-07-26 리비전 — 데이터 소스 정정 (버그 수정)**: 구 버전은 `discovered_companions`(런 종료 시점 RunManager의 검증 전 원본 발견 목록)를 그대로 표시했다. 하지만 `#14 영구 진행`의 `commit_run_end(discovered_ids, floor)`는 `#10 동료 데이터`에 존재하지 않는 id를 `push_warning` 후 걸러내고 실제로 해금된 id만 `newly_unlocked`에 담아 `progress_committed` 신호로 발신한다. 원본 목록을 그대로 쓰면, 검증에 실패해 실제로는 해금되지 않은 id에 대해서도 "신규 해금!" 카드를 표시하는 오류가 발생한다. 따라서 이 화면은 반드시 `#14`가 검증까지 마친 `newly_unlocked`만 사용한다.

### 화면 구성

| 섹션 | 내용 |
|------|------|
| 결과 헤더 | "성공!" (is_success=true) 또는 "패배" (is_success=false) |
| 도달 층수 | "X층 도달" + "최고 기록!" 배지 (is_new_record=true 시) |
| 이번 런 신규 해금 동료 | 발견 동료 카드 목록. 없으면 "발견한 동료 없음 · 다음 런에서 새로운 동료를 만나보세요" (2026-07-26 추가 — 아래 참조) |
| 해금 진행도 | "해금 동료: X / 4명". 4/4 도달 시 "모든 동료를 발견했습니다!"로 대체 (2026-07-26 추가) |
| 메인메뉴 버튼 | → 메인메뉴 전환 |

### 흐름 (2026-07-26 리비전 — 실제 호출 체인 반영)

```
RunManager.end_run(success: bool) 호출
  ↓
#13이 ProgressManager.commit_run_end(discovered_ids, floor) 호출
  ↓
#13이 progress_committed(newly_unlocked, save_success) 신호 수신 대기(await)
  ↓
#13이 newly_unlocked·is_new_record를 결과 데이터에 담아 SceneManager.go_to(S-06 RunResultScreen, FADE) 호출
  ↓
결과 화면 표시 (화면 진입 시 데이터 조회 — 이 시점에는 항상 저장 처리가 끝나 있음)
  ↓
"메인메뉴로" 버튼 탭 → (광고 통합 #18 처리 후) → SceneManager.go_to(S-02 MainMenu, FADE)
```

구 버전은 "#14가 먼저 처리 → #14 처리 완료 신호 수신"으로 뭉뚱그려 있었으나, 실제로는 #16이 #14와 직접 통신하지 않는다 — 호출과 신호 수신 모두 #13이 수행하고, #16은 #13이 완성한 결과 데이터를 받기만 한다.

### Core Rules

1. **저장 완료 후 화면 표시** (2026-07-26 리비전 — 검증 가능한 형태로 재기술): #13이 `progress_committed` 신호를 수신한 이후에만 #16으로 제어가 넘어온다 → 결과 화면이 표시될 때는 항상 해금이 저장 시도까지 완료된 상태 (성공/실패 여부는 `save_success`로 별도 판단, #17의 소관).
2. **최고 기록 계산은 #14**: 이 시스템은 `is_new_record` 값을 받아 표시만 한다.
3. **빈 발견 목록 처리**: `newly_unlocked = []` → "발견한 동료 없음" 표시. 정상 케이스.
4. **광고는 메인메뉴 전환 시**: "메인메뉴로" 버튼 탭 → #18 광고 통합 호출 → 광고 완료 후 씬 전환.

## Formulas

수치 공식 없음.


## Edge Cases

- **이번 런 newly_unlocked가 이미 해금된 동료 포함**: `#14.commit_run_end()`가 이미 해금된 id를 `newly_unlocked`에 다시 담지 않으므로 (중복 방지) 발생하지 않는다.

- **동시 승리 판정** (2026-07-26 리비전 — 표현 정정): `is_success=true`로 전달됨. 근거는 `#6 전투 공식`의 고정된 데미지 적용 순서(공격자 → 방어자)상 승리가 항상 먼저 확정되기 때문이며, 이는 우선순위 규칙이 아니라 고정 순서의 자연스러운 결과다 (`#1 턴제 전투`가 이 순서를 보장). 구 버전의 "승리 우선" 표현은 마치 별도의 우선순위 판정이 존재하는 것처럼 읽혀 `#6`/`#1` 리비전에서 이미 정정된 표현과 어긋났다.

- **신규 해금도 신기록도 없는 완전한 실패** (2026-07-26 추가): `newly_unlocked=[]` AND `is_new_record=false`인 경우, 결과 화면은 "발견한 동료 없음 · 다음 런에서 새로운 동료를 만나보세요" 고정 문구로 최소한의 격려를 제공한다 (새 데이터 의존성 없음 — 순수 UI 카피).

- **0층 도달 (1층 1번 방 즉사)**: `floor_reached=1` (1층에 진입했으므로). "1층 도달" 표시.

- **#18 광고 통합 실패**: #18 Core Rule — 5초 타임아웃 후 강제 콜백 → 씬 전환 진행. 결과 화면이 광고 실패로 블록되지 않음.

## Acceptance Criteria

(2026-07-26 리비전 — AC1~6은 렌더링 주장을 데이터 바인딩 주장으로 축소. 실제 화면 렌더링 검증은 `#20 UI/HUD`의 AC 범위.)

1. (승리 표시) GIVEN `is_success=true` WHEN 결과 화면 데이터 구성 THEN 헤더 바인딩 값이 "성공!"이다.

2. (패배 표시) GIVEN `is_success=false` WHEN 결과 화면 데이터 구성 THEN 헤더 바인딩 값이 "패배"이다.

3. (신규 해금 동료 표시, 2026-07-26 리비전 — 예시 ID 일반화) GIVEN `newly_unlocked`에 정확히 하나의 동료 ID가 담긴 상태 WHEN 결과 화면 데이터 구성 THEN 동료 카드 목록 바인딩 데이터에 그 ID가 정확히 포함된다.

4. (빈 발견 목록) GIVEN `newly_unlocked=[]` WHEN 결과 화면 데이터 구성 THEN 발견 동료 영역 바인딩 텍스트가 "발견한 동료 없음 · 다음 런에서 새로운 동료를 만나보세요"이다.

5. (최고 기록 배지) GIVEN `is_new_record=true` WHEN 데이터 구성 THEN 층수 옆 배지 바인딩 값이 "최고 기록!"이다.

6. (해금 진행도) GIVEN 총 4명 중 2명 해금 WHEN 결과 화면 데이터 구성 THEN 진행도 바인딩 텍스트가 "해금 동료: 2 / 4명"이다.

6b. (전체 해금 완료, 2026-07-26 추가) GIVEN 총 4명 중 4명 해금 WHEN 결과 화면 데이터 구성 THEN 진행도 바인딩 텍스트가 "모든 동료를 발견했습니다!"이다 (분수 텍스트로 대체되지 않음).

7. (메인메뉴 전환) GIVEN "메인메뉴로" 버튼 탭 WHEN 처리 THEN #18 광고 통합 → (광고 완료 후) `SceneManager.go_to(S-02, FADE)`가 호출된다.

8. (저장 완료 후 표시, 2026-07-26 리비전 — 검증 가능한 형태로 재기술) GIVEN 이 시스템이 결과 화면 표시 흐름을 시작하는 시점 THEN `#13`이 `#14`의 `progress_committed` 신호를 이미 수신한 이후다 (신호 수신 전에는 이 시스템으로 제어가 넘어오지 않는다 — `#14`의 저장 디스크 I/O 자체가 아니라 이 시스템의 진입 시점 가드를 검증 대상으로 한다).
