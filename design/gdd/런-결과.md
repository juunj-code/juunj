## Overview

런 결과 시스템은 런 종료 시 결과 화면을 표시하는 Progression 레이어 시스템이다. #13 RunManager로부터 런 종료 신호와 결과 데이터(승패, 도달 층수, 이번 런 발견 동료)를 받아 화면을 구성하고, #14 영구 진행에서 갱신된 해금 상태·최고 기록을 추가로 표시한다. 플레이어가 확인하면 메인메뉴로 돌아간다. 이 시스템은 화면 오케스트레이션만 담당하며, 영구 데이터 처리는 #14가 이 화면 표시 전에 완료한 상태다.

## Player Fantasy

"이 런 실패했지만 ○○는 해금됐다." — 실패해도 뭔가 남는다는 감각. 성공 시 "최고 기록 갱신!" 피드백.

## Detailed Rules

### 결과 화면 데이터

#13 RunManager `end_run()` 완료 후 이 시스템에 전달:

```gdscript
# 결과 화면 구성에 필요한 데이터
{
  "is_success": bool,
  "floor_reached": int,                        # 1~3
  "discovered_companions": Array[String],       # 이번 런 신규 발견 동료 ID (#14 처리 전 RunManager 보유값)
  "is_new_record": bool                         # #14가 최고 층수 갱신 여부 계산 후 전달
}
```

### 화면 구성

| 섹션 | 내용 |
|------|------|
| 결과 헤더 | "성공!" (is_success=true) 또는 "패배" (is_success=false) |
| 도달 층수 | "X층 도달" + "최고 기록!" 배지 (is_new_record=true 시) |
| 이번 런 신규 해금 동료 | 발견 동료 카드 목록. 없으면 "발견한 동료 없음" |
| 해금 진행도 | "해금 동료: X / 4명" |
| 메인메뉴 버튼 | → 메인메뉴 전환 |

### 흐름

```
RunManager.end_run(success: bool) 호출
  ↓
#14 영구 진행이 먼저 처리 (discovered_companions 해금 + 최고 기록 갱신 + 저장)
  ↓
#14 처리 완료 신호 수신
  ↓
SceneManager.go_to(S-06 RunResultScreen, FADE)
  ↓
결과 화면 표시 (화면 진입 시 데이터 조회)
  ↓
"메인메뉴로" 버튼 탭 → (광고 통합 #18 처리 후) → SceneManager.go_to(S-02 MainMenu, FADE)
```

### Core Rules

1. **저장 완료 후 화면 표시**: #14 처리 완료 후 씬 전환 → 결과 화면이 표시될 때는 항상 해금이 저장된 상태.
2. **최고 기록 계산은 #14**: 이 시스템은 `is_new_record` 값을 받아 표시만 한다.
3. **빈 발견 목록 처리**: `discovered_companions = []` → "발견한 동료 없음" 표시. 정상 케이스.
4. **광고는 메인메뉴 전환 시**: "메인메뉴로" 버튼 탭 → #18 광고 통합 호출 → 광고 완료 후 씬 전환.

## Formulas

수치 공식 없음.

**해금 진행도 표시:**
```
unlocked_count = len(ProgressManager.get_unlocked_companions())
total_companions = 4  # MVP: 기본1 + 히든3
표시: "해금 동료: {unlocked_count} / {total_companions}명"
```

## Edge Cases

- **이번 런 discovered_companions가 이미 해금된 동료 포함**: #3 동료 해금이 이미 `discovered_companions`에 추가하지 않으므로 (중복 방지) 발생하지 않는다.

- **동시 승리 판정**: #6 전투 공식 기준 승리 우선 → `is_success=true`로 전달됨 (#1 턴제 전투 보장).

- **0층 도달 (1층 1번 방 즉사)**: `floor_reached=1` (1층에 진입했으므로). "1층 도달" 표시.

- **#18 광고 통합 실패**: #18 Core Rule — 5초 타임아웃 후 강제 콜백 → 씬 전환 진행. 결과 화면이 광고 실패로 블록되지 않음.

## UI Requirements

RunResultScreen (S-06) 구성 (`#20 UI/HUD` 소유):
1. **결과 헤더** — "성공!" (초록 강조) / "패배" (빨강 강조)
2. **도달 층수** — "X층 도달" + "최고 기록!" 배지 (is_new_record 시)
3. **이번 런 신규 해금 동료** — 동료 카드 (초상화 + 이름), 없으면 "발견한 동료 없음"
4. **해금 진행도** — "해금 동료: X / 4명"
5. **"메인메뉴로" 버튼** — 탭 → #18 광고 → S-02

## Acceptance Criteria

1. (승리 표시) GIVEN `is_success=true` WHEN 결과 화면 표시 THEN "성공!" 헤더가 표시된다.

2. (패배 표시) GIVEN `is_success=false` WHEN 결과 화면 표시 THEN "패배" 헤더가 표시된다.

3. (신규 해금 동료 표시) GIVEN `discovered_companions=["hidden_archer_03"]` WHEN 결과 화면 표시 THEN archer_03 동료 카드가 표시된다.

4. (빈 발견 목록) GIVEN `discovered_companions=[]` WHEN 결과 화면 표시 THEN "발견한 동료 없음" 텍스트가 표시된다.

5. (최고 기록 배지) GIVEN `is_new_record=true` WHEN 표시 THEN "최고 기록!" 배지가 층수 옆에 표시된다.

6. (해금 진행도) GIVEN 총 4명 중 2명 해금 WHEN 결과 화면 표시 THEN "해금 동료: 2 / 4명" 텍스트가 표시된다.

7. (메인메뉴 전환) GIVEN "메인메뉴로" 버튼 탭 WHEN 처리 THEN #18 광고 통합 → (광고 완료 후) `SceneManager.go_to(S-02, FADE)`가 호출된다.

8. (저장 완료 후 표시) GIVEN RunResult 화면이 표시될 때 THEN #14 영구 진행의 저장 처리가 이미 완료된 상태다.
