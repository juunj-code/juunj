## Overview

적 데이터 시스템은 바람의 탑 게임 내 모든 적(Enemy)의 **정적 블루프린트**를 정의하는 Foundation 레이어 시스템이다. 각 적의 이름·스탯(HP/공격력/방어력/속도)·스킬 참조·처치 시 보상(경험치 등) 같은 "전투마다 변하지 않는 고정 정보"를 담은 데이터 구조체이며, #1 턴제 전투·#6 전투 공식·#7 적 AI 3개 시스템의 공통 기반으로 동작한다. 적의 행동 패턴(공격적/방어적 같은 AI 로직)은 이 시스템이 아닌 #7 적 AI가 소유하며, 전투 중 동적 상태(현재 HP 등)는 #13 런 상태 관리가 소유한다. 이 시스템은 #10 동료 데이터와 함께 전투 밸런스의 기준점 역할을 하며, 동료 스탯 범위(base_hp 60~150 등)와 대비되는 적 스탯 범위를 확정해 #6 전투 공식이 참조할 입력값을 제공한다. MVP에서는 3층 던전에 등장할 일반 적 3종 + 보스 1종을 정의한다.

## Player Fantasy

플레이어는 "적 데이터 시스템"을 인식하지 않는다. 대신 전투 한 판 한 판에서 "이 적, 패턴이 읽힌다"는 감각과 "졌다면 내 실수지, 불공정한 게 아니다"는 신뢰를 경험한다.

적 데이터 시스템이 만드는 감각:
- **읽히는 위협**: 적의 스탯이 명확한 역할(빠르고 약한 놈 / 느리고 단단한 놈)을 가져서, 플레이어가 한두 턴 안에 "이 녀석부터 잡아야겠다"는 판단을 내릴 수 있다.
- **공정한 도전**: 필라 3(솔로도 최강)을 뒷받침 — 어떤 적도 파티 구성과 전략으로 극복 가능해야 하며, 무작위 즉사나 회피 불가능한 패턴은 없다.
- **보스의 짜릿함**: 일반 적과 확연히 다른 스탯 곡선(더 높은 HP, 더 위협적인 스킬)으로 "이건 진짜 보스다"가 스탯만 봐도 체감된다.

플레이어는 데이터 구조를 경험하지 않는다. 전투 중 "이 적 패턴을 파악했다"는 성취감과, 죽었을 때 "내가 준비가 부족했다"는 납득을 경험한다.

*(creative-director 미상담 — Lean 모드. Production 진입 전 수동 검토 권장)*

## Detailed Design

### Core Rules

**EnemyData 스키마** (GDScript — `EnemyData extends Resource`):

```gdscript
class_name EnemyData
extends Resource

# 식별자
@export var id: String            # 고유 ID (예: "goblin_01", "boss_wind_guardian")
@export var name: String          # 표시 이름 (예: "고블린 정찰병")

# 시각
@export var sprite_id: String     # 전투 스프라이트 ID

# 기본 스탯 (전투마다 고정)
@export var base_hp: int    # 기본 최대 HP
@export var base_atk: int   # 기본 공격력
@export var base_def: int   # 기본 방어력
@export var base_spd: int   # 기본 속도 (턴 순서 결정)

# 스킬
@export var skill_id: String  # SkillData 리소스 참조 ID (MVP: 정확히 1개, 보스도 동일)

# 등급
@export var is_boss: bool = false  # true = 보스 — 스탯 곡선 상향 + 전투 UI 특수 표시
```

**파일 위치:** `assets/data/enemies/[id].tres`

`skill_id`는 #10 동료 데이터가 정의한 `SkillData` 리소스를 그대로 재사용한다 (별도 EnemySkillData 없음 — 스킬 스키마는 동료/적 공통).

### States and Transitions

적 데이터 자체는 **불변(immutable)** — 상태 전이 없음. 적 라이프사이클은 다른 시스템이 관리:

| 상태 | 관리 시스템 | 설명 |
|------|-------------|------|
| 스폰 대기 | #2 랜덤 던전 | 어느 방에 어떤 적을 배치할지 결정 |
| 전투 중 | #13 런 상태 관리 | 현재 HP, 상태이상 — 이 시스템은 소유하지 않음 |
| 처치됨 | #1 턴제 전투 | 전투 종료 판정에 반영. 동료와 달리 영속 저장 없음 (적은 해금 개념 없음) |

### Interactions with Other Systems

| 소비 시스템 | 읽는 필드 | 목적 |
|-------------|-----------|------|
| #1 턴제 전투 | base_atk, base_def, base_hp, base_spd, skill_id | 전투 스탯 및 스킬 실행 |
| #2 랜덤 던전 | id, is_boss | 방 타입별 적 스폰 (일반방=일반 적, 보스방=보스) |
| #6 전투 공식 | base_atk, base_def, base_hp | 데미지 공식 입력값 범위 |
| #7 적 AI | base_atk, base_spd, skill_id | 행동 우선순위 결정 (AI 행동 로직 자체는 이 시스템이 소유하지 않음) |

**데이터 소유권 경계** (혼동 방지):

| 데이터 | 소유 시스템 |
|--------|-------------|
| 적 블루프린트 (스탯, 스킬) | **이 시스템** (#11) |
| 런 내 현재 HP / 버프 | #13 런 상태 관리 |
| 어느 방에 어떤 적 배치 | #2 랜덤 던전 |
| 적 행동 로직 (AI) | #7 적 AI |

*(specialist agent 미상담 — Lean 모드. Production 진입 전 수동 검토 권장)*

## Formulas

이 시스템은 계산 공식이 없는 순수 데이터 시스템이다. 대신 #6 전투 공식이 입력값으로 사용할 **적 스탯 범위**를 여기서 확정한다. 범위는 #10 동료 데이터가 정의한 스탯 범위(base_hp 60~150, base_atk 10~30, base_def 5~20, base_spd 1~10)를 기준점으로 삼아, "그룹전(적 1~3마리)에서 즉사 없이, 보스는 격이 다르게" 원칙으로 산정했다.

**스탯 범위 정의:**

| 스탯 | 심볼 | 타입 | 일반 적 범위 | 보스 범위 | 설명 |
|------|------|------|--------------|-----------|------|
| 기본 최대 HP | `base_hp` | int | 25 ~ 65 | 150 ~ 300 | 일반 적은 동료 HP 최저치(60)보다 낮게 → 여러 마리가 빠르게 정리되는 리듬. 보스는 동료 HP 상한(150)을 하한선으로 → 1:1에서도 격이 다름을 체감 |
| 기본 공격력 | `base_atk` | int | 8 ~ 18 | 15 ~ 25 | 그룹 공격 시 동료 HP 최저치(60)의 절반을 넘지 않도록 상한을 눌러 즉사 방지 |
| 기본 방어력 | `base_def` | int | 3 ~ 12 | 10 ~ 20 | 일반 적은 낮게 → "때리는 맛". 보스는 동료 DEF 상한까지 → 지구전 유도 |
| 기본 속도 | `base_spd` | int | 1 ~ 9 | 4 ~ 9 | 보스는 하한을 4로 올려 매 턴 확실히 개입 (존재감 없는 보스 방지) |

**MVP 4종 예시 배분 (참고용 — 실제 밸런스는 프로토타입에서 검증):**

| 유형 | base_hp | base_atk | base_def | base_spd | 컨셉 |
|------|---------|----------|----------|----------|------|
| 일반 적 A (속도형) | 30 | 16 | 4 | 8 | 먼저 치고 빠지는 글래스 캐논 |
| 일반 적 B (밸런스형) | 45 | 13 | 7 | 5 | 무난한 표준 적, 기준점 역할 |
| 일반 적 C (탱커형) | 65 | 10 | 12 | 2 | 느리지만 오래 버팀 |
| 보스 | 220 | 20 | 16 | 6 | HP·DEF 모두 동료 상한 초과 — 격이 다름이 즉시 체감 |

> 이 범위는 #6 전투 공식 GDD의 데미지 계산 입력 범위가 된다. 전투 공식 GDD 작성 전에 변경이 필요하면 이 GDD를 먼저 수정한다.
> 즉사 방지 검증 앵커: "적 ATK × 스킬 배율 − 동료 DEF 최저치(5)"가 동료 HP 최저치(60)의 절반을 넘지 않는 선. 정확한 계수는 #6 전투 공식에서 확정.

## Edge Cases

- **적 3마리가 모두 같은 파티원을 타겟팅하는 경우**: 이 조합은 이론상 동료 HP 최저치(60)에 근접하거나 초과하는 데미지를 한 턴에 줄 수 있다(일반 적 ATK 상한 18 × 3마리 완전 관통 가정 시). 이 GDD는 스탯 범위만 소유하며 타겟팅 로직은 소유하지 않는다 — `#7 적 AI`는 반드시 타겟 분산 규칙(예: 동일 타겟 연속 지정 확률 감소, 또는 마리당 최대 1회 행동 제한)을 포함해야 하며, 이 제약은 `#7 적 AI` GDD 작성 시 확정한다.

- **중복된 `id`를 가진 `.tres` 파일이 2개 이상 로드된 경우**: 로딩 시 `push_error("Duplicate enemy id: [id]")` 출력 + 첫 번째로 로드된 데이터만 사용. 두 번째 이후는 무시. (동료 데이터와 동일 규칙)

- **`skill_id`가 존재하지 않는 스킬을 참조하는 경우**: `#1 턴제 전투`가 SkillData 로드 실패 감지 → `skill_id = "skill_basic_attack"`(기본 공격)으로 fallback. `push_warning("Missing skill: [skill_id], falling back to basic_attack")` 로그 출력. (동료 데이터와 동일 규칙 — SkillData 공유이므로 fallback도 동일)

- **`sprite_id`가 비어 있거나 해당 스프라이트가 없는 경우**: fallback 스프라이트(`sprite_missing.png`) 사용. null 참조 에러 없이 게임 진행 유지.

- **스탯 값이 정의된 범위를 초과하는 경우** (예: `is_boss = false`인데 `base_hp > 65`, 또는 `is_boss = true`인데 `base_hp < 150`): 데이터 오류로 간주. 로드 시 `push_warning("Enemy [id] stat out of expected range for is_boss=[value]")` 출력하되 게임은 해당 값 그대로 사용 (강제 클램핑 없음 — 디자이너가 의도적으로 범위 밖 값을 테스트할 수 있어야 함). 동료 데이터와 동일 원칙.

- **던전 방에 배치할 적 데이터가 없는 경우** (예: `#2 랜덤 던전`이 빈 방 유형에 적을 요청): 이 시스템은 해당 상황을 감지하지 않는다 — 적어도 MVP 4종(일반 3 + 보스 1)이 항상 존재함을 전제로 하며, 방 배치 실패는 `#2 랜덤 던전`의 책임 범위.

## Visual/Audio Requirements

이 시스템은 시각 자산을 소유하지 않는다 — 스프라이트 렌더링은 `#1 턴제 전투`/`#20 UI/HUD`가, 오디오는 `#21 오디오`가 소유한다. 이 시스템의 책임은 아트 바이블이 요구하는 시각적 차별화를 `sprite_id`/`is_boss` 필드로 지원 가능하게 하는 것뿐이다.

**아트 바이블 준수 요구사항** (design/art/art-bible.md):
- 실루엣(섹션 3-1): 일반 적은 오목/비대칭 실루엣(소형: 삼각 돌출 2개+, 중형: 역삼각형 상반신/비대칭 팔) 필수. 보스는 동료 스프라이트 면적 4배 이상 + 내부 네거티브 스페이스 1개 이상 — `is_boss=true` 적의 `sprite_id` 에셋은 이 크기 기준을 충족해야 한다.
- 색상(섹션 4-2): 적 관련 시각 요소(rim light, 위험 표시)는 위협홍 계열(`H:0–15°`, 기준색 `#C0392B`)만 사용하며, 동료 warm 계열(`H:280°–130°`)과 최소 30° 차이를 유지한다.
- 배치(섹션 3-2): 보스 방은 십자형 레이아웃 예정(*GDD 확정 후 조정*) — 스폰 공간 요구사항 자체는 `#2 랜덤 던전` 소유.

오디오: 이 시스템은 오디오 필드를 갖지 않는다(SkillData/EnemyData에 sfx 참조 없음). 적 조우/피격 SFX는 `#21 오디오`가 `#1 턴제 전투` 이벤트에 훅을 걸어 재생한다.

## UI Requirements

이 시스템은 UI를 소유하지 않는다. 전투 중 적 이름·HP·상태 표시는 `#20 UI/HUD`가 담당하며, `EnemyData.name`과 초기 `base_hp`를 데이터 소스로 참조한다(실시간 HP는 `#13 런 상태 관리` 소유). 아트 바이블 섹션 3-3(사각형 단일 원칙, 최소 터치 44×44px)은 `#20 UI/HUD` GDD 작성 시 적용 대상.

## Acceptance Criteria

1. **GIVEN** 게임이 시작될 때, **WHEN** `assets/data/enemies/` 경로의 EnemyData 파일들을 로드하면, **THEN** MVP 4종(노멀 3종 + 보스 1종)이 모두 오류 없이 로드되고, 각각 고유한 `id`를 가진다.

2. **GIVEN** 로드된 EnemyData 리소스 하나를 검사할 때, **WHEN** 필드를 확인하면, **THEN** `id`/`name`/`sprite_id`/`base_hp`/`base_atk`/`base_def`/`base_spd`/`skill_id`/`is_boss` 9개 필드가 모두 정의된 타입으로 채워져 있고, 경로가 `assets/data/enemies/[id].tres` 규칙을 따른다.

3. **GIVEN** EnemyData가 로드된 상태에서, **WHEN** 전투 중 HP·상태이상이 변화한 뒤 EnemyData 리소스를 다시 조회하면, **THEN** `base_hp`/`base_atk`/`base_def`/`base_spd` 원본 값은 변하지 않는다 (실시간 상태는 #13 런 상태 관리 소유, EnemyData는 불변).

4. **GIVEN** #1 턴제 전투가 전투를 시작할 때, **WHEN** EnemyData의 전투 스탯 필드를 조회하면, **THEN** 조회값이 전투 시작 시점 적의 초기 스탯·사용 스킬과 정확히 일치한다.

5. **GIVEN** #2 랜덤 던전이 방에 적을 배치할 때, **WHEN** `id`/`is_boss`를 조회하면, **THEN** `is_boss=true` 데이터는 보스룸 후보로만, `is_boss=false` 데이터는 일반룸 후보로만 식별된다.

6. **GIVEN** 노멀 적 3종(속도형/밸런스형/탱커형) 데이터를 검사할 때, **WHEN** 스탯을 확인하면, **THEN** `base_hp`/`base_atk`/`base_def`/`base_spd`가 각각 25–65 / 8–18 / 3–12 / 1–9 범위 내에 있고, GDD 예시 배분(속도형 30/16/4/8, 밸런스형 45/13/7/5, 탱커형 65/10/12/2)과 정확히 일치한다.

7. **GIVEN** 보스 데이터를 검사할 때, **WHEN** 스탯을 확인하면, **THEN** `base_hp`/`base_atk`/`base_def`/`base_spd`가 각각 150–300 / 15–25 / 10–20 / 4–9 범위 내에 있고, GDD 예시 배분(220/20/16/6)과 정확히 일치한다.

8. **GIVEN** 두 `.tres` 파일이 동일한 `id`를 가질 때, **WHEN** 로드 시퀀스를 실행하면, **THEN** `push_error`가 기록되고 먼저 로드된 데이터만 유효하며 두 번째는 무시된다.

9. **GIVEN** `skill_id`가 존재하지 않는 SkillData를 참조할 때, **WHEN** #1 턴제 전투가 스킬을 로드하면, **THEN** 로드 실패가 감지되고 `skill_basic_attack`으로 대체되며 `push_warning`이 기록된다.

10. **GIVEN** `sprite_id`가 비어있거나 파일이 없을 때, **WHEN** 스프라이트를 렌더링하면, **THEN** `sprite_missing.png`로 대체되고 null 참조 크래시 없이 진행된다.

11. **GIVEN** `is_boss=false`인 적의 `base_hp`가 65를 초과하는 등 정의된 범위를 벗어날 때, **WHEN** 데이터를 로드하면, **THEN** `push_warning`이 기록되지만 값은 강제 clamp 없이 입력된 그대로 유지된다.

12. **GIVEN** #7 적 AI가 행동 우선순위 계산을 위해 EnemyData를 조회할 때, **WHEN** `base_atk`/`base_spd`/`skill_id`를 요청하면, **THEN** 세 값 모두 정상 반환되며 데이터 미제공으로 인한 예외가 발생하지 않는다 (AI 알고리즘 자체의 정오는 #7 GDD 검증 범위).
