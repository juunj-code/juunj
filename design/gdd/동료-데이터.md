# 동료 데이터 (Companion Data)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-22
> **Implements Pillar**: 발견의 기쁨 / 성장은 영원하다

## Overview

동료 데이터 시스템은 바람의 탑 게임 내 모든 동료(Companion)의 **정적 블루프린트**를 정의하는 Foundation 레이어 시스템이다. 각 동료의 이름·초상화 ID·클래스 타입·기본 스탯(HP/공격력/방어력/속도)·스킬 참조·히든 여부·해금 조건 등 "런에 상관없이 변하지 않는 정보"를 담은 데이터 구조체이며, 총 9개 하위 시스템의 공통 기반으로 동작한다. 런 내 동적 상태(현재 HP, 버프 등)는 이 시스템이 아닌 #13 런 상태 관리가 소유하고, 해금 여부는 #14 영구 진행이 소유한다. 플레이어 관점에서 동료 데이터는 "히든 동료를 처음 발견하는 순간" 화면에 즉각 나타나는 이름·고유 컬러·짧은 사연의 원천이다 — 이 데이터가 없으면 "발견의 기쁨" 필라 자체가 성립하지 않는다. MVP에서는 동료 4명(기본 1명 + 히든 3명)을 정의하며, Full Vision에서 최대 20명까지 확장된다.

## Player Fantasy

"이 동료... 내가 처음 찾은 거다."

히든 동료를 발견하는 순간은 우연이 아닌 탐색의 보상이다. 플레이어는 동료 데이터가 무엇인지 알 필요가 없다 — 단지 이름이 뜨고, 고유한 따뜻한 컬러가 어두운 던전에 번지고, 두 줄의 사연이 눈에 들어오는 그 순간을 경험할 뿐이다.

동료 데이터 시스템이 만드는 감각:
- **수집의 쾌감**: 도감에 빈칸이 채워지는 느낌. "아직 못 찾은 동료가 몇 명이나 더 있을까?"
- **애착 형성의 씨앗**: 이름과 짧은 사연 하나로 동료가 "유닛"이 아닌 "캐릭터"가 된다.
- **성장의 물리적 증거**: 런이 끝나도 이 동료는 내 로스터에 남는다. 실패한 런이 아무것도 아닌 런이 되지 않는 이유.

플레이어는 "동료 데이터 시스템"을 경험하는 것이 아니다. 처음 만나는 동료의 이름을 기억하고, 그 동료와 함께 다음 런을 시작하고 싶은 마음이 생기는 것을 경험한다.

## Detailed Design

### Core Rules

**CompanionData 스키마** (GDScript — `CompanionData extends Resource`):

```gdscript
class_name CompanionData
extends Resource

# 식별자
@export var id: String            # 고유 ID (예: "warrior_01", "hidden_mage_02")
@export var name: String          # 표시 이름 (예: "검사 아이라")
@export var description: String   # 1~2줄 사연

# 시각
@export var portrait_id: String       # 초상화 스프라이트 ID
@export var color_accent_hex: String  # 고유 컬러 포인트 (예: "#C0392B") — 아트 바이블 H:280°~H:130° 범위 준수

# 기본 스탯 (런과 무관하게 고정)
@export var base_hp: int    # 기본 최대 HP
@export var base_atk: int   # 기본 공격력
@export var base_def: int   # 기본 방어력
@export var base_spd: int   # 기본 속도 (턴 순서 결정)

# 스킬
@export var skill_id: String  # SkillData 리소스 참조 ID (MVP: 정확히 1개)

# 해금
@export var is_hidden: bool = false       # true = 히든 동료 (기본값 false)
@export var unlock_condition_id: String   # #9 히든 트리거 참조 ID ("" = 기본 동료)
```

**SkillData 스키마** (별도 리소스 — 이 GDD에서 구조 정의, 스킬 GDD에서 상세화):

```gdscript
class_name SkillData
extends Resource

@export var id: String
@export var name: String
@export var description: String
@export var damage_multiplier: float = 1.0  # 기본 공격력 대비 배율
@export var effect_id: String               # 상태이상 참조 ID ("" = 없음) — #12 상태이상 참조
@export var cost_sp: int = 0                # 스킬 포인트 소모량
```

**파일 위치:**
- CompanionData: `assets/data/companions/[id].tres`
- SkillData: `assets/data/skills/[skill_id].tres`

### States and Transitions

동료 데이터 자체는 **불변(immutable)** — 상태 전이 없음. 동료 라이프사이클은 다른 시스템이 관리:

| 상태 | 관리 시스템 | 설명 |
|------|-------------|------|
| 미발견 | #14 영구 진행 | 히든 동료, 도감 미등록 |
| 해금됨 | #14 영구 진행 | 발견 후 영구 로스터 추가 |
| 파티 편성 중 | #15 파티 구성 | 현재 런에서 선택된 상태 |
| 전투 중 | #13 런 상태 관리 | 현재 HP, 상태이상 — 이 시스템은 소유하지 않음 |

## Formulas

이 시스템은 계산 공식이 없는 순수 데이터 시스템이다. 대신 #6 전투 공식이 입력값으로 사용할 **스탯 범위**를 여기서 확정한다.

**스탯 범위 정의:**

| 스탯 | 심볼 | 타입 | 범위 | 설명 |
|------|------|------|------|------|
| 기본 최대 HP | `base_hp` | int | 60 ~ 150 | 낮을수록 딜러, 높을수록 탱커 성향 |
| 기본 공격력 | `base_atk` | int | 10 ~ 30 | 기본 공격 데미지의 원천 |
| 기본 방어력 | `base_def` | int | 5 ~ 20 | 받는 데미지 감소 |
| 기본 속도 | `base_spd` | int | 1 ~ 10 | 높을수록 먼저 행동 (턴 순서) |

**MVP 4명 예시 배분 (참고용 — 실제 캐릭터 미확정):**

| 역할 유형 | base_hp | base_atk | base_def | base_spd |
|-----------|---------|----------|----------|----------|
| 탱커 성향 | 150 | 12 | 20 | 3 |
| 밸런스 (기본 동료) | 100 | 18 | 12 | 6 |
| 딜러 성향 | 70 | 28 | 7 | 8 |
| 지원 성향 | 80 | 14 | 10 | 9 |

> 이 범위는 #6 전투 공식 GDD의 데미지 계산 입력 범위가 된다. 전투 공식 GDD 작성 전에 변경이 필요하면 이 GDD를 먼저 수정한다.

## Edge Cases

- **기본 동료의 해금 조건이 없는 경우**: `is_hidden = false`, `unlock_condition_id = ""` — 런 시작 시 파티 선택 화면에 항상 표시. `#14 영구 진행`은 이 동료를 "기본 해금" 상태로 초기화한다.

- **이미 해금된 히든 동료를 같은 런에서 다시 발견한 경우**: `#3 동료 해금`이 `#14 영구 진행`을 조회 → 이미 등록 확인 → 해금 스킵. "이미 동료가 되어 있어요" 메시지 표시. CompanionData는 변경 없음.

- **`portrait_id`가 비어 있거나 해당 스프라이트가 없는 경우**: `portrait_id = ""` 또는 파일 미존재 시 fallback 초상화 스프라이트(`portrait_missing.png`) 사용. null 참조 에러 없이 게임 진행 유지.

- **같은 `id`를 가진 `.tres` 파일이 2개 이상 로드된 경우**: 로딩 시 `push_error("Duplicate companion id: [id]")` 출력 + 첫 번째로 로드된 데이터만 사용. 두 번째 이후는 무시. 빌드 검증 도구가 이를 경고로 잡아야 한다(Acceptance Criteria 참조).

- **`skill_id`가 존재하지 않는 스킬을 참조하는 경우**: `#1 턴제 전투`가 SkillData 로드 실패 감지 → `skill_id = "skill_basic_attack"`(기본 공격)으로 fallback. `push_warning("Missing skill: [skill_id], falling back to basic_attack")` 로그 출력.

- **스탯 값이 정의된 범위를 초과하는 경우** (`base_hp < 60` 또는 `base_hp > 150` 등): 데이터 오류로 간주. 로드 시 `push_warning` 출력하되 게임은 해당 값 그대로 사용 (강제 클램핑 없음 — 디자이너가 범위 외 값을 의도적으로 테스트할 수 있어야 함).

## Dependencies

### Upstream Dependencies (이 시스템이 의존하는 것)

없음. Foundation 레이어 — 다른 어떤 시스템에도 의존하지 않는다.

### Downstream Dependents (이 시스템에 의존하는 것)

| 시스템 | 의존 유형 | 기대하는 인터페이스 |
|--------|-----------|---------------------|
| #1 턴제 전투 | **Hard** — 없으면 전투 불가 | `base_hp`, `base_atk`, `base_def`, `base_spd`, `skill_id` |
| #3 동료 해금 | **Hard** — 없으면 해금 연출 불가 | `id`, `name`, `description`, `portrait_id`, `color_accent_hex`, `is_hidden` |
| #4 장비 | **Hard** — 보정 기준값 없음 | `base_atk`, `base_def` |
| #6 전투 공식 | **Hard** — 입력 범위 정의 불가 | 스탯 범위 (Formulas 섹션 참조) |
| #7 적 AI | **Soft** — AI 동작은 하되 타겟 우선순위 단순화됨 | `base_atk`, `base_spd` |
| #8 시너지 | **Hard** — 조합 계산 불가 | `id`, `skill_id` |
| #9 히든 트리거 | **Hard** — 조건 평가 기준 없음 | `unlock_condition_id` |
| #14 영구 진행 | **Hard** — 저장할 대상 정의 불가 | `id`, `is_hidden` |
| #15 파티 구성 | **Hard** — 선택 UI 표시 불가 | `id`, `name`, `portrait_id`, `is_hidden` |

> 양방향 일관성 주의: 위 시스템들의 GDD에는 이 GDD(`design/gdd/동료-데이터.md`)가 Dependencies 섹션에 명시되어야 한다.

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 너무 낮을 때 | 너무 높을 때 |
|--------|-----------|-----------|-------------|-------------|
| `base_hp` 최솟값 | 60 | 40 ~ 80 | 적 1번 공격에 즉사 → 불공평감 | 최솟값과 최댓값 차이 없어짐 |
| `base_hp` 최댓값 | 150 | 120 ~ 200 | 탱커 역할 의미 없음 | 전투 1회가 너무 길어짐 |
| `base_atk` 최솟값 | 10 | 8 ~ 15 | 기본 공격이 의미 없음 | 스킬과 기본 공격 격차 없음 |
| `base_atk` 최댓값 | 30 | 25 ~ 40 | 딜러 역할 의미 없음 | 탱커 즉사 → 방어 의미 없음 |
| `base_def` 최솟값 | 5 | 2 ~ 8 | 딜러가 너무 취약 | 방어 없는 동료 선택 동기 없음 |
| `base_def` 최댓값 | 20 | 15 ~ 25 | 탱커 역할 의미 없음 | 탱커가 적 공격 완전 무효화 |
| `base_spd` 최솟값 | 1 | 1 ~ 3 | 느린 동료가 행동 못 함 | 속도 차이 없어짐 |
| `base_spd` 최댓값 | 10 | 8 ~ 12 | 빠른 동료 선택 동기 없음 | 속도 동료가 항상 2번 선행 → 불균형 |
| MVP 총 동료 수 | 4 | 4 (MVP 고정) | 파티 조합 없음 | 스코프 초과 |
| Full Vision 총 동료 수 | 20 | 15 ~ 24 | 도감 완성 동기 약함 | 개성 있는 설계 불가능 (솔로 개발) |

## Acceptance Criteria

1. **GIVEN** 게임이 시작될 때, **WHEN** CompanionData 파일들을 로드하면, **THEN** MVP 4명 동료가 모두 오류 없이 로드되고, 각각 고유한 `id`를 가진다.

2. **GIVEN** 기본 동료 (`is_hidden = false`, `unlock_condition_id = ""`), **WHEN** 런 시작 시 파티 선택 화면을 열면, **THEN** 해당 동료가 선택 가능 목록에 즉시 표시된다.

3. **GIVEN** 히든 동료 3명 (`is_hidden = true`), **WHEN** 해금 전 파티 선택 화면을 열면, **THEN** 해당 동료들은 선택 목록에 표시되지 않거나 "???" 상태로 잠금 표시된다.

4. **GIVEN** CompanionData를 로드했을 때, **WHEN** 각 동료의 `skill_id` 필드를 확인하면, **THEN** 정확히 1개의 `skill_id`가 있고 해당 SkillData 파일이 존재한다.

5. **GIVEN** 중복된 `id`를 가진 CompanionData 파일 2개가 있을 때, **WHEN** 게임이 데이터를 로드하면, **THEN** `push_error`가 출력되고 첫 번째 파일만 사용되며 게임이 중단되지 않는다.

6. **GIVEN** CompanionData의 스탯이 정의된 범위 내 (`base_hp: 60~150` 등), **WHEN** #6 전투 공식이 이 값을 사용하면, **THEN** 데미지 계산이 음수 또는 0이 되지 않고 전투가 최소 1턴 진행된다.

7. **GIVEN** `portrait_id`가 비어 있는 CompanionData, **WHEN** UI가 초상화를 표시하려 할 때, **THEN** fallback 스프라이트(`portrait_missing.png`)가 표시되고 null 오류 없이 게임이 진행된다.
