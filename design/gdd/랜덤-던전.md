# 랜덤 던전 (Random Dungeon)

> **Status**: In Design
> **Author**: 사용자 + Claude Code
> **Last Updated**: 2026-07-24
> **Implements Pillar**: 발견의 기쁨
> **Creative Director Review**: Skipped — Lean 모드

## Overview

랜덤 던전 시스템은 매 런마다 고유한 3층 던전 구조를 생성하는 Feature 레이어 시스템이다. 완전한 절차적 타일맵 생성 대신 **사전 제작 방(Room) 유형을 조합**하는 방식을 택한다 — 구현 부담은 낮추고, 발견의 예측 불가능성은 유지한다. 각 층은 3~4개의 방으로 구성되며, 방 유형(전투·히든·보스)의 배치 규칙에 따라 순서가 결정된다. 이 시스템은 "어떤 방이 이 위치에 오는가"를 결정하고 #13 런 상태 관리에 현재 층·방 정보를 제공하며, 방 입장 시 #9 히든 트리거·#11 적 데이터에 연결한다.

## Player Fantasy

"이 층에 히든 방이 있을까?" — 플레이어가 경로를 선택할 때마다 드는 기대감.

방 구성이 매 런 달라야 "어제 갔던 길을 오늘도 간다"는 느낌을 없앨 수 있다. 동시에 완전 무작위는 "이번 런은 히든 방이 하나도 없었다"는 박탈감을 준다 — 히든 방은 **런당 최소 1개 보장**이 발견의 기쁨을 지킨다.

## Detailed Rules

### 방 유형 카탈로그

| 유형 | ID | 내용 | MVP 개수 |
|------|----|------|---------|
| 전투방 | `combat` | 적 그룹 조우 (#11 데이터) | 다수 |
| 히든방 | `hidden` | 히든 동료·아이템 발견 (#9 트리거) | 런당 1~2개 |
| 보스방 | `boss` | 보스 적 1마리 (#11 is_boss=true) | 층당 1개 (최종 층만) |

휴식방·상점방: YAGNI — Vertical Slice 이후.

### 층 구조 규칙

| 층 | 방 수 | 구성 |
|----|-------|------|
| 1층 | 3개 | 전투 2 + (히든 0~1) |
| 2층 | 3개 | 전투 2 + (히든 0~1) |
| 3층 | 3개 | 전투 1 + (히든 0~1) + 보스 1 (마지막) |

**히든방 보장 규칙**: 1층·2층 중 적어도 하나에는 히든방이 반드시 1개 존재. 3층에도 50% 확률로 1개. → 런당 히든방 최소 1개, 최대 3개.

### 방 배치 알고리즘

```
층 생성 (floor_index: 1~3):
  1. 기본 전투방 수 결정 (위 표 참조)
  2. 히든방 여부 결정:
       - 1층: 히든방 없으면 전체 런에 히든방 강제 1개 배치
       - 2층: 1층에 히든방 없었으면 강제, 있었으면 50%
       - 3층: 50%
  3. 방 목록 생성 후 셔플 (단, 보스방은 항상 마지막)
  4. RunManager에 층 데이터 저장
```

# ponytail: 단순 확률 기반 배치. 보장 로직이 복잡해지면 가중치 테이블로 교체.

### 방 간 이동

MVP: 선형 구조 — 방은 1→2→3→(다음 층 or 런 종료) 순서로만 이동. 분기 선택 없음.

분기 경로(두 길 중 선택): Vertical Slice 이후. 분기가 "발견의 기쁨" 핵심이지만 MVP 스코프에서 제외 — 먼저 선형 구조로 코어 루프를 검증한다.

### Core Rules

1. **보스방은 항상 마지막**: 3층의 마지막 방은 항상 보스방.
2. **히든방 최소 보장**: 런당 최소 1개 히든방. 생성 시 보장 로직 적용.
3. **방 데이터는 런 시작 시 전체 생성**: 층별로 지연 생성 안 함 — 미리 생성해 RunManager에 저장.
4. **적 배치는 이 시스템이 결정**: 전투방에 어떤 적이 등장할지 #11 EnemyData 목록에서 선택. 보스방은 is_boss=true 데이터 고정.

### 전투방 적 구성

| 층 | 적 수 | 구성 |
|----|-------|------|
| 1층 | 2마리 | 일반 적 2마리 (랜덤 조합) |
| 2층 | 3마리 | 일반 적 3마리 |
| 3층 (전투방) | 3마리 | 일반 적 3마리 |
| 보스방 | 1마리 | 보스 고정 |

## Formulas

**히든방 배치 확률:**

| 층 | 조건 | 히든방 배치 |
|----|------|------------|
| 1층 | 항상 | 50% 확률 (단, 2층도 50% 실패 시 → 3층 강제) |
| 2층 | 1층 히든방 없음 | 강제 배치 |
| 2층 | 1층 히든방 있음 | 50% 확률 |
| 3층 | 항상 | 50% 확률 |

최종 보장: `1층 miss AND 2층 miss` → 3층 강제 배치. 런당 히든방 = 1 ~ 3개.

**전투방 적 선택:**
```
enemies = random.sample(normal_enemy_pool, k=room_enemy_count)
```
동일 적 2마리 허용 (MVP 적 종류가 3종뿐이므로).

## Edge Cases

- **히든방 강제 배치 시 3층 보스방과 충돌**: 3층은 [전투방, (히든방), 보스방] 순서 — 히든방이 강제 배치되어도 보스방은 마지막 고정이므로 충돌 없음.

- **히든방 진입 시 플레이어가 이미 해당 동료를 해금한 경우**: #9 히든 트리거가 조건 평가 — 이미 해금된 동료의 방은 "빈 방" 또는 "장비 드롭 방"으로 대체. 이 GDD는 대체 내용을 결정하지 않음 — #9 히든 트리거 소유.

- **정확히 3종 적만 있는 MVP에서 3마리 적 방 구성**: 같은 적이 중복될 수 있음. 의도된 동작 — 적 다양성은 Full Vision에서 확장.

## Tuning Knobs

| 조정값 | 현재 설정 | 안전 범위 | 설명 |
|--------|-----------|-----------|------|
| 층당 방 수 | 3개 | 3~5 | 늘릴수록 런 시간 증가 |
| 히든방 확률 | 50% | 30~70% | 너무 낮으면 발견 빈도 감소 |
| 최대 히든방/런 | 3개 | 2~4 | 희소성 조절 |
| 1~2층 적 수 | 2→3마리 | 1~3 | 1층 2마리로 시작해 점진 증가 |

## Visual/Audio Requirements

이 시스템은 방 데이터 구조만 생성한다. 던전 시각 표현(타일맵, 방 외형, 미니맵)은 DungeonScreen 씬과 `#20 UI/HUD` 소유.

히든방 발견 연출: #9 히든 트리거 신호 → #3 동료 해금 처리. 이 시스템은 "히든방에 진입했다"는 이벤트 발신만 담당.

## UI Requirements

이 시스템은 UI를 소유하지 않는다. 현재 층/방 표시, 이동 버튼은 `#20 UI/HUD` 소유.

## Acceptance Criteria

1. (히든방 보장) GIVEN 1층·2층 생성 시 모두 히든방 배치 실패 WHEN 3층이 생성되면 THEN 3층에 히든방이 강제 포함된다.

2. (보스방 위치) GIVEN 3층 방 목록이 생성될 때 WHEN 방 순서를 확인하면 THEN 마지막 방은 항상 보스방이다.

3. (적 배치) GIVEN 1층 전투방 진입 WHEN 적 목록을 확인하면 THEN 일반 적(is_boss=false) 2마리가 배치되어 있다.

4. (보스방 적) GIVEN 3층 보스방 진입 WHEN 적 목록을 확인하면 THEN is_boss=true인 적 1마리만 있다.

5. (런 시작 시 전체 생성) GIVEN 런이 시작될 때 WHEN RunManager를 확인하면 THEN 3개 층 전체의 방 데이터가 이미 생성되어 있다.

6. (히든방 최대) GIVEN 확률이 모두 히든방으로 결정될 때 WHEN 전체 런 방 목록을 확인하면 THEN 히든방은 최대 3개이다.
