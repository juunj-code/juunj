# 랜덤 던전 (Random Dungeon)

> **Status**: In Design
> **Author**: 사용자 + Claude Code

> **Creative Director Review**: Skipped — Lean 모드

## Overview

랜덤 던전 시스템은 매 런마다 고유한 3층 던전 구조를 생성하는 Feature 레이어 시스템이다. 완전한 절차적 타일맵 생성 대신 **사전 제작 방(Room) 유형을 조합**하는 방식을 택한다 — 구현 부담은 낮추고, 발견의 예측 불가능성은 유지한다. 각 층은 3~4개의 방으로 구성되며, 방 유형(전투·히든·보스)의 배치 규칙에 따라 순서가 결정된다. 이 시스템은 "어떤 방이 이 위치에 오는가"를 결정하고 #13 런 상태 관리에 현재 층·방 정보를 제공하며, 방 입장 시 #9 히든 트리거·#11 적 데이터에 연결한다.

## Player Fantasy

"이 다음 방엔 뭐가 있을까?" (2026-07-26 리비전 — MVP는 분기 선택이 없으므로 "경로 선택" 기대감이 아니라 "다음 방 공개" 기대감으로 정정. 경로 선택형 기대감은 Open Questions #1의 분기 시스템이 실제로 구현된 이후에나 성립한다.)

방 구성이 매 런 달라야 "어제 갔던 길을 오늘도 간다"는 느낌을 없앨 수 있다. 동시에 완전 무작위는 "이번 런은 히든 방이 하나도 없었다"는 박탈감을 준다 — 히든 방은 **런당 최소 1개 보장**이 발견의 기쁨을 지킨다.

## Detailed Rules

### 방 유형 카탈로그

| 유형 | ID | 내용 | MVP 개수 |
|------|----|------|---------|
| 전투방 | `combat` | 적 그룹 조우 (#11 데이터) | 다수 |
| 히든방 | `hidden` | 히든 동료·아이템 발견 (#9 트리거) | 런당 1~2개 |
| 보스방 | `boss` | 보스 적 1마리 (#11 is_boss=true) | 층당 1개 (최종 층만) |

휴식방·상점방: YAGNI — Vertical Slice 이후.

### 층 구조 규칙

| 층 | 방 수 | 구성 |
|----|-------|------|
| 1층 | 3개 | 전투 2 + (히든 0~1) |
| 2층 | 3개 | 전투 2 + (히든 0~1) |
| 3층 | 3개 | 전투 1 + (히든 0~1) + 보스 1 (마지막) |

**히든방 보장 규칙 (2026-07-26 리비전 — 보장이 실제로 완성되는 시점 정정)**: 1층은 50% 확률로 히든방 배치. 1층이 miss면 2층은 **강제** 배치(100%) — 즉 "런당 최소 1개" 보장은 **2층이 끝나는 시점에 이미 100% 완성**된다(1층 hit이거나, 1층 miss+2층 강제 hit이거나, 둘 중 하나는 항상 참). 3층의 50% 롤은 보장과 무관한 **보너스 확률**일 뿐이다. → 런당 히든방 최소 1개(2층까지 확정), 최대 3개(1·2·3층 모두 hit).

### 방 배치 알고리즘

```
층 생성 (floor_index: 1~3, rng: RandomNumberGenerator):  # 2026-07-26 리비전: rng를 외부 주입받음 — 테스트에서 결정적 결과 강제 가능
  1. 기본 전투방 수 결정 (위 표 참조)
  2. 히든방 여부 결정:
       - 1층: rng 기반 50% 확률
       - 2층: 1층에 히든방 없었으면 강제(100%), 있었으면 rng 기반 50%
       - 3층: rng 기반 50% (보장과 무관한 보너스 확률)
  3. 방 목록 생성: 보스방이 아닌 방들만 뽑아 Fisher-Yates 셔플(rng 사용) 후, 보스방(3층 한정)을 배열 끝에 추가
     — 전체를 셔플한 뒤 보스방 위치를 나중에 "고치는" 방식이 아니라, 애초에 셔플 대상에서 보스방을 제외한다.
  3b. 히든방 각각에 대해: `#9 히든 트리거`.`get_next_companion_id()` 호출 → 반환된 id를 해당 방의 `companion_id`로 설정 (2026-07-26 추가 — 배정 로직 자체는 `#9`가 소유, 이 시스템은 방 타입 결정 후 호출만 함)
  4. RunManager에 층 데이터 저장
```

# ponytail: 단순 확률 기반 배치. 보장 로직이 복잡해지면 가중치 테이블로 교체.

### 방 간 이동

MVP: 선형 구조 — 방은 1→2→3→(다음 층 or 런 종료) 순서로만 이동. 분기 선택 없음.

분기 경로(두 길 중 선택): Vertical Slice 이후. 분기가 "발견의 기쁨" 핵심이지만 MVP 스코프에서 제외 — 먼저 선형 구조로 코어 루프를 검증한다.

### Core Rules

1. **보스방은 항상 마지막**: 3층의 마지막 방은 항상 보스방.
2. **히든방 최소 보장**: 런당 최소 1개 히든방 — 2층 생성이 끝나는 시점에 이미 확정됨(2층의 강제 배치 규칙이 유일한 보장 메커니즘). 3층 롤은 보너스일 뿐 보장에 관여하지 않는다.
3. **방 데이터는 런 시작 시 전체 생성**: 층별로 지연 생성 안 함 — 미리 생성해 RunManager에 저장.
4. **적 배치는 이 시스템이 결정**: 전투방에 어떤 적이 등장할지 #11 EnemyData 목록에서 선택. 보스방은 is_boss=true 데이터 고정.

### 전투방 적 구성

| 층 | 적 수 | 구성 |
|----|-------|------|
| 1층 | 2마리 | 일반 적 2마리 (랜덤 조합) |
| 2층 | 3마리 | 일반 적 3마리 |
| 3층 (전투방) | 3마리 | 일반 적 3마리 |
| 보스방 | 1마리 | 보스 고정 |

## Formulas

**히든방 배치 확률 (2026-07-26 리비전 — 도달 불가능한 조건 삭제):**

| 층 | 조건 | 히든방 배치 |
|----|------|------------|
| 1층 | 항상 | 50% 확률 |
| 2층 | 1층 히든방 없음 | **강제 배치(100%)** — 이 규칙만으로 "런당 최소 1개" 보장이 완성됨 |
| 2층 | 1층 히든방 있음 | 50% 확률 |
| 3층 | 항상 | 50% 확률 (보장과 무관한 보너스 롤) |

(구 버전의 "1층 miss AND 2층 miss → 3층 강제" 조건은 삭제됨 — 2층 규칙이 1층 miss 시 이미 100% 강제이므로 이 조건은 확률 0으로 도달 불가능했다. 런당 히든방 = 1 ~ 3개, 최소값은 항상 1층 또는 2층에서 확정된다.)

**전투방 적 선택 (2026-07-26 리비전 — 샘플링 방식 수정):**
```
enemies = []
for i in range(room_enemy_count):
  enemies.append(normal_enemy_pool[rng.randi() % normal_enemy_pool.size()])  # 복원추출 — 중복 허용
```
동일 적 2마리 이상 허용 (MVP 적 종류가 3종뿐이므로). **구 버전은 `random.sample`(비복원추출, 중복 불가) 의사코드를 썼으나, 그러면 room_enemy_count=3·pool 크기=3인 2층/3층에서 항상 3종 전부가 고정 출현해 "랜덤 조합"이 성립하지 않았다** — 복원추출로 수정.

## Edge Cases

- **히든방 강제 배치 시 3층 보스방과 충돌**: 3층은 [전투방, (히든방), 보스방] 순서 — 히든방이 강제 배치되어도 보스방은 마지막 고정이므로 충돌 없음.

- **히든방 진입 시 플레이어가 이미 해당 동료를 해금한 경우**: #9 히든 트리거가 조건 평가 — 이미 해금된 동료의 방은 "빈 방" 또는 "장비 드롭 방"으로 대체. 이 GDD는 대체 내용을 결정하지 않음 — #9 히든 트리거 소유.

- **정확히 3종 적만 있는 MVP에서 3마리 적 방 구성**: 같은 적이 중복될 수 있음. 의도된 동작 — 적 다양성은 Full Vision에서 확장. (2026-07-26 리비전 — 리뷰 노트: 3종 풀이라 플레이어가 1층에서 이미 전 종류를 보게 되고, 2~3층 "새로운" 방은 조합의 개체 수 차이만 다를 뿐 신규 발견은 없다 — 사실상 다양성 상한. Full Vision 확장 전까지 받아들이는 MVP 트레이드오프로 명시.)

- **UI가 다음 방 정보를 미리 노출하는 경우 (2026-07-26 추가 — 리뷰에서 발견된 미명시 제약)**: 이 시스템의 "발견" 판타지는 플레이어가 다음 방 유형을 진입 전까지 모른다는 전제에 전적으로 의존한다. `#20 UI/HUD`는 미니맵·경로 미리보기 등 어떤 형태로도 진입 전 방 유형을 노출해서는 안 된다 — 이 제약은 Downstream Dependents에 명시(참조).

## Acceptance Criteria

1. (히든방 보장 — 2층 강제, 2026-07-26 재작성) GIVEN 주입된 rng가 1층 히든방 배치를 miss로 반환하는 상태에서 WHEN 2층이 생성되면 THEN 2층에 히든방이 강제 포함된다 (rng 값과 무관 — 100% 확정). (구 AC는 "1층·2층 모두 실패"를 전제했으나, 2층 규칙이 1층 실패 시 이미 100% 강제이므로 그 전제 자체가 발생 불가능했다 — 실제 보장 메커니즘을 직접 검증하도록 재작성.)

1b. (히든방 확률 분기, 2026-07-26 추가) GIVEN 주입된 rng가 1층 히든방 배치를 hit으로 반환하는 상태에서 WHEN 2층이 생성되면 THEN 2층 히든방 배치는 (강제가 아닌) rng의 50% 확률 결과를 따른다.

2. (보스방 위치) GIVEN 3층 방 목록이 생성될 때 WHEN 방 순서를 확인하면 THEN 마지막 방은 항상 보스방이다.

2b. (보스방 유일성, 2026-07-26 추가) GIVEN 3층 방 목록이 생성될 때 WHEN 전체 방을 순회하면 THEN `is_boss=true`인 방은 정확히 1개이고, 그 방은 배열의 마지막 인덱스이다.

3. (적 배치, 2026-07-26 리비전 — 중복 허용 명시) GIVEN 1층 전투방 진입 WHEN 적 목록을 확인하면 THEN 일반 적(is_boss=false) 2마리가 배치되어 있으며, 두 마리는 같은 종일 수도 다른 종일 수도 있다(복원추출).

4. (보스방 적) GIVEN 3층 보스방 진입 WHEN 적 목록을 확인하면 THEN is_boss=true인 적 1마리만 있다.

5. (런 시작 시 전체 생성) GIVEN 런이 시작될 때 WHEN RunManager를 확인하면 THEN 3개 층 전체의 방 데이터가 이미 생성되어 있다.

6. (히든방 최대, 2026-07-26 리비전 — 주입 rng 명시) GIVEN 주입된 rng가 1층·2층·3층 히든방 배치를 모두 hit으로 반환하는 상태에서 WHEN 전체 런 방 목록을 확인하면 THEN 히든방은 정확히 3개이며 이 이상 배치되지 않는다.
