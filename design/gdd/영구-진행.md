> **Status**: In Design
> **Author**: 사용자 + Claude Code

## Overview

영구 진행 시스템은 런과 런 사이에 **영속되는 플레이어 진행 상황** — 해금된 동료 목록과 최고 층수 기록 — 을 소유하고 관리하는 Progression 레이어 시스템이다. 런이 종료되면 #13 런 상태 관리로부터 "이번 런 발견 동료 목록"을 받아 해금 처리를 수행하고, #17 로컬 세이브를 통해 디스크에 기록한다. 게임 시작 시에는 로컬 세이브에서 복원해 #15 파티 구성 등 소비 시스템에 "현재 사용 가능한 동료 목록"을 제공한다. 이 시스템은 필라 2("성장은 영원하다")의 기술적 실현체로, 런이 실패해도 발견한 동료는 반드시 남는다는 약속을 보장한다.

## Player Fantasy

"이 런 실패했지만 ○○는 해금됐다."

런 결과 화면에서 새 동료 카드가 펼쳐지는 순간 — 그 "그래도 얻었다"는 감각이 이 시스템이 만드는 전부다. 런이 끝날 때마다 뭔가 남는다는 확신이 다음 런을 시작하게 만든다.

반대로 이 시스템이 실패하면: 해금했던 동료가 다음 게임 세션에 없다. #17 로컬 세이브와 함께 "신뢰"가 깨지는 가장 치명적인 버그 유형이다.

## Detailed Rules

### 소유 데이터

```gdscript
# ProgressManager Autoload (또는 RunManager와 통합 고려 — Open Questions 참조)

var unlocked_companions: Array[String] = []  # companion id 목록
var highest_floor_reached: int = 0
```

MVP에서 영구 진행 데이터는 이 두 필드가 전부다. 경험치·레벨·골드·업그레이드는 YAGNI.

### 초기화 (게임 시작 시)

```
1. #17 로컬 세이브 → load_section("companion_unlocks") → unlocked_companions 복원
2. #17 로컬 세이브 → load_section("floor_reached") → highest_floor_reached 복원
3. No Save Found 상태: unlocked_companions = [BASE_COMPANION_ID], highest_floor_reached = 0
```

`BASE_COMPANION_ID`: 기본 동료 1명 고정 상수 (예: `"warrior_base_01"`). 이 ID는 항상 해금 상태로 시작.

### 런 종료 시 처리

```
1. #13 RunManager.discovered_companions 수신
2. 각 id에 대해: if id not in unlocked_companions → unlock_companion(id)
3. if run_floor > highest_floor_reached → highest_floor_reached = run_floor
4. save() → #17 로컬 세이브에 두 섹션 저장
```

### 핵심 API

| 메서드 | 입력 | 출력 | 설명 |
|--------|------|------|------|
| `unlock_companion(id)` | String | void | 목록 추가 + 즉시 저장 |
| `is_unlocked(id)` | String | bool | 해금 여부 조회 |
| `get_unlocked_companions()` | — | Array[String] | 전체 해금 목록 반환 |
| `update_highest_floor(floor)` | int | void | 더 높으면 갱신 + 즉시 저장 |

### Core Rules

1. **해금은 단방향**: 한 번 해금된 동료는 절대 잠금 해제 불가. `unlocked_companions`에서 제거 없음.
2. **즉시 저장**: `unlock_companion()` 호출 즉시 #17 로컬 세이브 호출 — 런 종료 화면 표시 전에 저장 완료. 화면 표시 중 탭이 닫혀도 해금은 보존.
3. **기본 동료는 항상 해금**: 초기화 시 `BASE_COMPANION_ID`가 목록에 없으면 추가. 로컬 세이브 손상·초기화 후에도 기본 동료는 복구.
4. **#17 저장 실패 시 메모리 상태 유지**: 저장 실패해도 이번 세션의 `unlocked_companions`는 메모리에 유지 — 게임을 계속 진행할 수 있다. 단, 세션 종료 시 소실. UI에 "저장 실패" 알림 (#17 로컬 세이브가 신호 발신).

## Formulas

수치 공식 없음. 이 시스템의 "공식"은 아래 두 조건이다.

**해금 조건:**
```
unlock_companion(id) 실행 조건:
  id in RunManager.discovered_companions
  AND id not in unlocked_companions
```

**최고 기록 갱신 조건:**
```
update_highest_floor(floor) 실행 조건:
  floor > highest_floor_reached
```

## Edge Cases

- **같은 런에서 이미 해금된 동료를 다시 발견**: `is_unlocked(id) == true` → `unlock_companion()` 미호출. `#3 동료 해금`이 "이미 동료가 되어 있어요" 처리.

- **#17 저장 실패 후 게임 재시작**: 저장 직전까지의 상태만 복원됨 — 저장 실패한 런의 해금은 소실. 저장 실패 UI는 #17가 표시하므로 플레이어는 인지한 상태. 이 시스템은 "복구 재시도" 없음 — 책임은 #17 소유.

- **`unlocked_companions`가 비어 있는 세이브 파일 로드**: 손상 또는 비정상 데이터. Core Rule 3에 따라 `BASE_COMPANION_ID` 강제 추가 후 진행.

- **`discovered_companions`에 존재하지 않는 companion_id 포함**: `#10 동료 데이터`에서 해당 id 조회 실패 → `unlock_companion()` 미호출 + `push_warning("Unknown companion id: [id]")`. 유효하지 않은 id는 조용히 무시하지 않고 경고 기록.

- **최고 층수 0층 (런 실패, 1층도 못 깨고 전멸)**: `run_floor = 1`이 전달됨 (1층에 진입했으므로). `highest_floor_reached`는 0→1로 갱신. "1층 클리어" 기록이 아닌 "1층 도달" 기록.

## Dependencies

### Upstream Dependencies

| 시스템 | 의존 유형 | 사용하는 기능 |
|--------|-----------|---------------|
| #13 런 상태 관리 | **Hard** — 이번 런 발견 목록 없이 해금 불가 | `discovered_companions`, `current_floor` (런 종료 시) |

## Visual/Audio Requirements

이 시스템은 시각/오디오 자산을 소유하지 않는다. `unlock_companion()` 호출 시 `companion_unlocked` 신호를 발신 — `#3 동료 해금`이 연출을 처리한다.

## UI Requirements

이 시스템은 UI를 소유하지 않는다. 해금 목록·최고 기록 표시는 `#16 런 결과`·`#15 파티 구성` 소유.

## Acceptance Criteria

1. (초기화 – 신규) GIVEN 로컬 세이브가 없는 상태에서 WHEN 게임이 시작되면 THEN `unlocked_companions = [BASE_COMPANION_ID]`이고 `highest_floor_reached = 0`이다.

2. (초기화 – 복원) GIVEN `companion_unlocks: ["warrior_base_01", "hidden_mage_02"]`가 저장된 세이브가 있을 때 WHEN 게임이 시작되면 THEN `unlocked_companions`에 두 id가 모두 복원된다.

3. (해금 – 기본 흐름) GIVEN `unlocked_companions = ["warrior_base_01"]`인 상태에서 WHEN `unlock_companion("hidden_mage_02")`가 호출되면 THEN `unlocked_companions = ["warrior_base_01", "hidden_mage_02"]`이고 즉시 #17 로컬 세이브에 저장된다.

4. (해금 – 즉시 저장) GIVEN `unlock_companion("hidden_mage_02")`가 호출된 직후 WHEN 세션이 즉시 종료되면 THEN 다음 게임 시작 시 `"hidden_mage_02"`가 `unlocked_companions`에 있다.

5. (중복 해금 방지) GIVEN `unlocked_companions = ["warrior_base_01", "hidden_mage_02"]`인 상태에서 WHEN `unlock_companion("hidden_mage_02")`가 다시 호출되면 THEN `unlocked_companions`의 크기는 변하지 않는다 (중복 없음).

6. (최고 층수 갱신) GIVEN `highest_floor_reached = 2`인 상태에서 WHEN `update_highest_floor(3)`이 호출되면 THEN `highest_floor_reached = 3`이고 즉시 저장된다.

7. (최고 층수 미갱신) GIVEN `highest_floor_reached = 3`인 상태에서 WHEN `update_highest_floor(2)`가 호출되면 THEN `highest_floor_reached`는 3으로 유지된다.

8. (기본 동료 복구) GIVEN `unlocked_companions = []`인 손상 세이브가 복원된 상태에서 WHEN 초기화가 완료되면 THEN `unlocked_companions`에 `BASE_COMPANION_ID`가 포함된다.

9. (런 종료 연동) GIVEN 런이 종료되고 `discovered_companions = ["hidden_archer_03"]`이 RunManager에서 전달될 때 WHEN 영구 진행 처리가 실행되면 THEN `unlock_companion("hidden_archer_03")`이 호출되고 #17에 저장된다.

10. (유효하지 않은 id) GIVEN `discovered_companions = ["존재하지않는ID"]`가 전달될 때 WHEN 처리하면 THEN `push_warning`이 기록되고 `unlocked_companions`는 변하지 않으며 게임이 계속 진행된다.
